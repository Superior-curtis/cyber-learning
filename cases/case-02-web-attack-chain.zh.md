# 一條 Web 攻擊鏈：從掃描到提權

> 📅 2026-08-05 · 深入研究
> 一次真實的滲透測試，常常是一連串『小步驟』組成的鏈：掃描 → 列舉 → SQLi → 拿到 shell → 提權。這篇用一條完整的攻擊鏈案例，把 recon、web、提權三塊知識串起來。

---

**案例**：一台看起來「沒什麼」的 Web 伺服器，最後被拿到了 root。它不是被「一招打穿」，而是被**一連串小步驟**串成的一條鏈——每一步單獨看都不致命，合起來就是完整淪陷。

這篇把這條鏈走一遍，讓你把 `recon`、`web`、`提權` 三塊知識接成一個故事。

> 安全說明：這是一條授權滲透測試的鏈（對象是 lab-02-vulnerable-targets 那類靶機）。把它套到任何真實目標，就是入侵。每一環的防禦也在下面同等份量講到。

## 攻擊鏈拆解

#### 掃描

nmap 掃出開著的 80（HTTP）與 22（SSH）——目標面很小，但足以起步（kali-18）。

#### 列舉

gobuster 找到 `/admin.php` 與 `/?id=` 參數（kali-07）。

#### 注入

`?id=` 參數存在 SQL 注入——用參數化查詢該擋掉的東西沒擋（web-02）。

#### 拿到 shell

注入一路走到能寫檔，取得網頁伺服器權限的 shell。

#### 提權

發現 sudo 設定太寬 / SUID 檔——低權限爬到 root（kali-20）。

**看懂了嗎——沒有一招是「神奇漏洞」。** 每一步都是「前一環的結果 + 一個沒防好」。鏈的強度，取決於**最弱的一環**。

## 每一步的防禦

| 環節 | 防禦 |
|---|---|
| 掃描 | 最小攻擊面：只開必要的埠（`blue-01-hardening`） |
| 列舉 | 沒必要的路徑不該存在；`robots.txt` 不該洩漏結構 |
| 注入 | 參數化查詢（`web-02-injection`）——把鏈的這一段直接切斷 |
| shell | 最小權限執行 Web 服務、即時修補 |
| 提權 | 最小權限 + 打補丁（`kali-20-privilege-escalation`） |

> 記住攻擊鏈思維：防守不能只修「最出名的那環」，要每一環都扛得住。 攻擊者找的是鏈上最弱的一環；防守者就要讓每一環都夠硬。

## 偵測：鏈的任何一環都可能暴露

攻擊鏈的每一環，其實都會留下痕跡——`blue-02-logging-siem` 就是為了抓這些：

* 掃描：大量失敗連線到不同埠。
* 注入：異常的 SQL 語法出現在請求參數。
* shell：Web 進程突然執行非預期命令。

**藍隊不必等到「鏈完成」才發現——抓到任何一環，就能斷鏈。**

* 一招神奇的漏洞直接打穿

* 一連串小步驟，每一步都依賴前一環的結果；鏈的強度取決於最弱的一環

* 只要裝了防火牆就斷鏈

* 攻擊者一次完成所有步驟
