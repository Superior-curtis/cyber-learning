# 雲端設定錯誤

> 📅 2026-08-05 · 深入研究
> 雲端事故的頭號原因不是「被駭」，而是「設定錯誤」——公開的儲存桶、過寬的權限、沒關的端點。這篇拆開最常見的幾類設定錯誤，以及每一類的防禦。

---

`cloud-01-shared-responsibility` 告訴你「你那一半」你負責。而統計上，**雲端事故的頭號原因不是被駭，是設定錯誤**——一個勾沒勾好、一項權限給太寬。

這篇拆開最常見的幾類設定錯誤，以及每一類的防禦。

## 為什麼「設定錯誤」是頭號殺手

雲端把「安全設定」變成一堆**選項**：公開/私有、開啟/關閉、允許/拒絕。選項越多，勾錯的機率越大。而且雲端事故常常不是「攻擊成功」，而是**「本來就開著」**——攻擊者只是走進一扇沒鎖的門。

## 常見錯誤類別

| 錯誤 | 發生什麼 | 防禦 |
|---|---|---|
| 公開儲存桶 | 資料庫備份、金鑰、用戶資料被公開下載 | 預設私有、定期稽核公開權限 |
| IAM 過寬 | 給「所有資源」管理權限的帳號，離職還有效 | 最小權限、定期盤點、離職即撤 |
| 開放管理端點 | 資料庫、SSH 直接暴露公網 | 只允許內網/VPN、安全群組收緊 |
| 沒開加密 | 靜態資料裸存 | 開啟預設加密 |
| 沒開稽核 | 出事沒有日誌（`blue-02-logging-siem`） | 開啟稽核與集中日誌 |

> 把雲端設定錯誤想成「忘了鎖門」，而不是「鎖被撬開」。 它不需要高超技巧——只需要一個沒勾的框。所以雲端防守的重點是「盤點與稽核」，不是「對抗入侵」。

## 一個經典：公開的儲存桶

「公開儲存桶」是雲端設定錯誤的代表：某個放檔案的儲存服務，被設成「公開可讀」，於是你放在上面的備份、設定、甚至用戶資料，任何人都能直接下載。

它為什麼這麼常見？因為「公開」在開發時方便（測試、分享），而一旦設了公開，**很少人記得改回來或檢查**。防禦只有兩件事：

1. **預設私有**，公開要有明確理由與審批。
2. **定期掃描**誰的儲存桶是公開的。

## 防禦的一體兩面

設定錯誤的防禦，本質上是兩件事的反覆：

* **最小權限 + 最小暴露**：`blue-01-hardening` 與 `blue-07-iam-zero-trust` 的原則，在雲端一樣適用。
* **持續稽核**：定期掃描「哪些資源是公開的、哪些帳號權限過寬」——這正是 `cve-06-patch-management`「盤點」精神在雲端的版本。
