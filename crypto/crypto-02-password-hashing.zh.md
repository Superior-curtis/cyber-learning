# 密碼雜湊：bcrypt / argon2 為什麼贏

> 📅 2026-08-05 · 核心概念
> 同樣是雜湊，為什麼 MD5 早就出局、bcrypt 還屹立不搖、argon2 又成了新寵？關鍵在四個字：慢、加鹽、吃記憶體。這篇把密碼雜湊演算法講到你能自己選。

---

`pass-01-how-passwords-are-stored` 已經講過：密碼不能存明文，要存雜湊。但「用雜湊」跟「用對的雜湊」是兩回事——用錯演算法，等於把保險櫃的鎖換成一個生日鎖。

同樣都是雜湊，為什麼 MD5 早就出局、bcrypt 屹立不搖、argon2 又成了新寵？答案濃縮成四個字：**慢、加鹽、吃記憶體**。

## 快 = 壞：給攻擊者的禮物

先想一個反直覺的事。一般情況下，我們喜歡「快」的演算法——網頁載入越快越好。但密碼雜湊正好相反：**對密碼雜湊而言，快就是壞。**

為什麼？因為攻擊者拿到的不是你的密碼，而是雜湊值，他必須**猜**。猜的方法是把候選密碼一個一個雜湊出來比對——`pass-02-cracking-101` 把這套機制講得很透。這裡只要抓住關鍵：

> **演算法越快，攻擊者每秒能試的次數就越多；能試的次數越多，你的密碼就越早被試出來。**

所以「用 MD5 存密碼」基本上等於把破解速度開到最大。現代 GPU 每秒可以算幾十億次 MD5，一個普通密碼幾分鐘就沒了。

## 四種候選

要「慢」，人類設計出了幾個專門給密碼用的演算法。先看名單：

| 演算法 | 誕生 | 特色 | 現在的地位 |
|---|---|---|---|
| PBKDF2 | 2000 | 把一個雜湊反覆跑幾十萬次，靠「次數」拖慢 | 仍常見，但沒有內建抗 GPU |
| bcrypt | 1999 | 內建加鹽，cost factor 可調，抗 GPU 較好 | 老而彌堅，很多框架預設 |
| scrypt | 2009 | 除了算力，還要求**記憶體** | 抗 ASIC/GPU 更強 |
| argon2 | 2015 | 記憶體密集的現代設計，演算法競賽冠軍 | 目前公認最佳選擇 |

## 為什麼 bcrypt 特別受歡迎

bcrypt 能活二十年，靠兩個設計：

1. **內建隨機鹽（salt）**：每次雜湊都自動帶入一個隨機鹽，即使兩個使用者設了相同密碼，雜湊值也完全不同——這讓「預先算好的彩虹表」直接失效。
2. **可調的 cost factor**：你可以讓它「越算越慢」。今天的電腦比 1999 年快太多，所以把成本參數調高，讓單次計算依然要幾百毫秒，攻擊者每秒能試的次數就掉到個位數。

```
# 示意：bcrypt 的 cost factor 決定慢多少
# cost = 12 時，單次驗證約需 0.3 秒
# 攻擊者每秒只能試 3 個密碼，而非數億個
```

> 密碼雜湊的黃金指標：單次驗證約 100–300 毫秒。 對使用者只是「等一下」，對攻擊者卻是「每秒只能試幾個」。太快的雜湊，就是沒上鎖。

## argon2：目前的冠軍

argon2 是 2015 年密碼雜湊競賽（PHC）的贏家。它把「慢」做到了極致——不只是吃 CPU，還**大量吃記憶體**。記憶體是 GPU 和客製化晶片最難大量供應的資源，所以 argon2 對「用礦機暴力破解」特別有抵抗力。

argon2 有兩個版本：**argon2id** 是防守方的首選，因為它同時抵抗側信道與 GPU 攻擊。實務上，如果你今天要選，**argon2id 優先，其次 bcrypt，再其次 scrypt**。

## 怎麼選：一張決策表

| 你的情境 | 建議 |
|---|---|
| 新專案、沒包袱 | **argon2id** |
| 框架已經內建 bcrypt（例如很多 Web 框架預設） | 就用 bcrypt，把 cost factor 調到 100ms+ |
| 舊系統、想升級 | 在登入時「讀取即重雜湊」，逐步遷移到 argon2 |
| 任何情況 | 永遠不要用 MD5 / SHA-1 / 未加鹽的 SHA-256 存密碼 |

## 最常見的三個錯誤

* **用「普通」的雜湊存密碼**：MD5、SHA-1、甚至未加鹽的 SHA-256，都是設計給「資料完整性」的，速度快到不適合密碼。這正是 `pass-05-real-breaches` 裡幾次大災難的根源。
* **共用一個鹽**：鹽必須每個使用者獨立隨機。全站共鹽，等於沒有鹽。
* **自己發明演算法**：密碼學的第一原則是「不要自己發明」。bcrypt、argon2 這些演算法被密碼學家反覆打磨、攻擊過，才值得信任。

#### Q: 為什麼對密碼雜湊而言，「快」反而是壞事？

* 因為快的演算法會佔用太多 CPU

* 因為演算法越快，攻擊者每秒能嘗試的密碼越多，破解越快

* 因為快的演算法一定比較不安全

* 因為慢的演算法才能加鹽

> 💡 密碼破解是「猜密碼再雜湊比對」；演算法越快，每秒可嘗試的次數越多，弱密碼就越快被試出來。
