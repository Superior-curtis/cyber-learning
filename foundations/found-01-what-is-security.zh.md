# 資安是什麼：威脅、漏洞與風險

> 📅 2026-08-05 · 核心概念
> 資安不是買來的工具，而是一種思考習慣。這篇文章幫你建立整本書都賴以站立的骨架：資產、威脅、漏洞、風險。

---

有個朋友問我：「公司一直說我們有資安問題，到底是什麼意思？我們是小公司，誰會來找我麻煩。」好問題。「資安」聽起來像一個可以買回家的產品——防毒軟體、防火牆、號稱全包的「安全套件」。但資安其實是一段**「你在乎的東西」與「想傷害它的東西」之間的關係**。這段關係有四個零件，看懂之後，新聞裡每一則資安事件都會突然清楚起來。

這篇文章是整本書的大門。我們要蓋的骨架是：**資產 → 威脅 → 漏洞 → 風險**。後面每一篇文章，都掛在四個字上面。

這裡有個讓我真正想通的故事。一間小店老闆自認「防禦齊全」——高級監視器、最好的門鎖、還有警報器。結果一個小偷趁營業時間走進來，對員工笑了笑，拎著一台筆電就出去了。監視器和門鎖守錯了時段。**資安不是「有沒有防禦」的問題，而是「你有沒有為真正在乎的東西、對上真正的敵人，放對了防禦」。**

## 資安是關於你在乎什麼

要談資安，先要有想保護的東西。資安行話把它叫做**資產（asset）**——對你有價值、損失或受損會讓你心疼的任何東西。

資產不只有電腦。像是：

| 資產 | 例子 | 受損的樣貌 |
|---|---|---|
| **資料** | 客戶名單、程式碼、密碼 | 外洩、被刪、被勒索 |
| **系統** | 伺服器、筆電、手機 | 被接管、變磚、被操到卡頓 |
| **人** | 員工、客戶、你自己 | 被騙走祕密或金錢 |
| **名聲** | 大家對你的信任 | 一則新聞就歸零 |

為什麼要列資產？因為**資安不抽象。你不能防禦「網路」這個空泛的詞——你要防禦的是具體重要的東西。**一家說不出自己最寶貴資產是什麼的企業，根本無法排列優先順序；一個不知道自己守護什麼的防禦者，也只會把力氣花在錯的地方。

## 資安「不是」什麼

「資安」這兩個字被用得太浮濫，先把它身上的誤會清掉：

| 錯誤想法 | 實際情況 |
|---|---|
| 「資安是買得到的產品」 | 工具只是輔助，安全來自你圍繞它們做的決定與習慣 |
| 「資安是 IT 部門的事」 | 每個有權限的人都是防禦的一部分——尤其是「人」本身 |
| 「我們太小，不會被盯上」 | 攻擊者也很懶——他們專挑容易的下手，跟規模無關 |
| 「被駭了再來修」 | 那叫事件處理，比事前預防貴得多 |

最後一行特別值得記住。**沒有人計畫要出包，但有太多資安事件，是因為修補被排到了「之後」而發生的。**

## 那條鏈：資產 → 威脅 → 漏洞 → 風險

現在上骨架。它是一條鏈：每個字扣著下一個字。

* **資產（asset）**——你在乎的東西（如上）。
* **威脅（threat）**——可能傷害資產的人或事。威脅可能帶有*意圖*（攻擊者、小偷、競爭對手），也可能只是*天災*（火災、停電、壞掉的硬碟）。
* **漏洞（vulnerability）**——你的防禦裡可以讓威脅得手的弱點。程式的 bug、太弱的密碼、沒鎖的門、什麼都敢點的員工。
* **風險（risk）**——威脅真的利用漏洞去傷害資產的「機會」。風險才是你真正在乎的事情。

整個資安領域，就是**把風險縮小**這份工作——靠移除漏洞、偵測威脅、保護資產。

舉個具體的例子。假設資產是你的筆電：

| 環節 | 這個例子裡 |
|---|---|
| 資產 | 你的筆電，裝滿照片和學校檔案 |
| 威脅 | 想銷贓的偷筆電賊 |
| 漏洞 | 你根本沒設開機密碼 |
| 風險 | 很高——小偷拿了就能看光一切 |

小偷一直都在。是「漏洞」把你變成容易下手的目標。**你攔不住小偷，但你可以不當好下手的目標。**這一句話，就是防禦的核心。

## 認識你的威脅

不是所有威脅都一樣，而防禦的強度取決於你面對誰：

| 威脅行為者 | 他們是誰 | 典型目標 |
|---|---|---|
| **腳本小子** | 用現成工具、不太懂原理的初學者 | 炫耀、搞破壞 |
| **組織犯罪** | 專業集團 | 錢——勒索軟體、竊取資料、詐騙 |
| **國家級駭客** | 情報機構與軍隊 | 間諜、破壞、影響力 |
| **內部人員** | 已經在你組織裡的人 | 報復、貪婪、或單純疏忽 |

對大多數個人與小公司來說，**組織犯罪才是實際威脅**——而且手法通常很無聊：釣魚、弱密碼、沒修補的軟體。防禦一個國家級情報機構是完全不同的問題（也大多超出這本書的範圍）。知道敵人是誰，你就知道該多用力。

## 風險是決策的貨幣

這就是鏈之所以重要的原因：**真實世界裡，決策是用風險做的，不是用恐懼做的。**沒有系統能「完美安全」——永遠有你想不到的威脅、還沒發現的漏洞。所以防禦者不問「它安全嗎？」（這是個陷阱題——沒有東西是安全的），他們問：**「風險可以接受嗎？如果不能，該加哪一道控制？」**

這就是為什麼同一種登入頁面，在不同產品裡長得完全不一樣：

| 產品 | 風險評估的結論 | 結果 |
|---|---|---|
| 銀行 | 登入失敗的代價很高 | 驗證很多、步驟慢、很嚴格 |
| 公開新聞網站 | 登入失敗幾乎零成本 | 根本不需要帳號 |
| 討論區 | 帳號值得花一點力氣 | 密碼加驗證碼，夠了 |

同一個「登入」問題，三種答案，全部正確——因為風險不同。一旦你開始用資產、威脅、漏洞、風險去想，這些選擇就不再顯得隨便。

## 防禦者的心態

注意我們一直在做的事：我們會想「壞人」和「弱點」，但目標從來不是「變成更厲害的攻擊者」，而是相反。一個**防禦者**只問三個問題：

1. **我要保護什麼？**（資產）
2. **哪裡會出問題？**（威脅＋漏洞）
3. **我該怎麼做？**（控制）

整個技能就是這三問。本書的一切——密碼、網站安全、惡意程式、監控、事件處理——都是這三問的加深版。

好的防禦者還知道自己的盲點。最常見的資安失敗不是什麼高明駭客手法，而是一封**奏效的平凡 email**、一個**到處重複使用的密碼**、或一份**從沒測試過的備份**。戲劇性的零時差漏洞搶下新聞頭條，無聊的備份救了公司。請記得這件事。

> 限授權使用——本書是一本防禦導向、教育性質的參考書：它服務於你自己的系統、CTF 練習環境、以及獲得授權的測試（你擁有的環境，或你被允許進行的測試）。未經授權就去探測或攻擊別人的系統，在多數國家是違法的，甚至可能構成刑事犯罪。學防禦，不是學破壞。

## 所有防禦都在拉的三支槓桿

看懂風險之後，你就看得懂所有控制都在拉的三支槓桿：

| 槓桿 | 作用 | 例子 |
|---|---|---|
| **預防（Prevent）** | 讓攻擊失效 | 強密碼、修補漏洞 |
| **偵測（Detect）** | 發生時被你看見 | 日誌、告警、監控 |
| **應變（Respond）** | 控制損害並復原 | 備份、事件處理 |

真正的資安三種全用。光靠預防永遠不夠——遲早會漏。只偵測不應變，等於收到壞消息卻無能為力。**好的防禦是設計來「安全地失敗」：拖慢攻擊者、被你看見、而且還能復原。**

## 防禦者的第一天

骨架是理論；這裡把同一個想法變成一份實際的起步清單。每一項都對應本書後面的一篇文章：

| 起步動作 | 對應骨架的哪裡 | 深入閱讀 |
|---|---|---|
| 列出「失去會心痛」的資產 | 你無法防守你說不出名字的東西 | `found-04-threat-modeling` |
| 所有支援的地方都開啟 MFA | 縮小「弱密碼」這個漏洞 | `blue-07-iam-zero-trust` |
| 建立備份——而且要真的演練還原 | 把「應變」這支槓桿變成真的 | `blue-04-incident-response` |
| 準時修補，別再拖延更新 | 在被利用之前移除漏洞 | `cve-06-patch-management` |
| 用密碼管理器，別再一組密碼走天下 | 一次移除每個帳號上的同一個漏洞 | `pass-04-defenses` |

你不會一個下午做完這些。這份清單的意義在於它的形狀：**每一項真實的防禦，都是三支槓桿之一，套在你的一個資產上，瞄準一個威脅。**本書其餘的內容，都是細節。
