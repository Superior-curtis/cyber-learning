# 網路與 Web 運作基礎（HTTP / DNS / IP / Port）

> 📅 2026-08-05 · 核心概念
> 從敲下網址到網頁出現，中間發生什麼？DNS 把網域變成 IP，TCP/IP 建立連線，Port 決定服務，HTTP 交換訊息。這是一切的基礎。

---

你每天打開瀏覽器，敲進網址，網頁一秒出現。但這一秒裡，你的電腦其實完成了一場複雜的接力：先問路（DNS）、再通話（TCP/IP）、找到正確的門口（Port）、最後用一種共同的語言交換資料（HTTP）。資安文章裡幾乎所有攻擊與防禦，都建立在這些底層機制之上。

這篇是整個系列的「預修課程」。不管之後讀的是 `net-02-tls-https`、`recon-03-scanning-nmap` 還是 `web-02-injection`，你都需要先懂這一篇。看不懂這層，很多資安討論就像在聽外星語。

## 一次點擊的旅程

先看全景，再拆細節。你敲下網址並按下 Enter 之後，大概是這樣：

```text
瀏覽器輸入網址
↓
問 DNS：example.com 是哪個 IP？
↓
拿到 93.184.216.34
↓
與該 IP 的 443 埠建立 TCP 連線（TLS 加密）
↓
送出 HTTP GET /index.html
↓
收到 200 OK + HTML，瀏覽器開始渲染
```

每一步都可以拆成更細的機制。這一篇把每一棒都講清楚。

## DNS：把名字翻譯成地址

人類記得住網域名稱，但網路只認 IP。DNS（Domain Name System）就是網際網路的電話簿：把 `example.com` 翻譯成 `93.184.216.34` 這種格式的地址。

查詢的過程不是一次到底，而是層層往上問：

#### 瀏覽器先問自己的快取

前幾天查過？有的話直接用，最快。

#### 問遞迴解析器

通常是你的 ISP 或 8.8.8.8 這類公共 DNS，它代為跑完剩下的流程。

#### 問根伺服器與頂層網域

根伺服器指向 .com 的伺服器，.com 再指向負責 example.com 的權威伺服器。

#### 拿到權威答案

權威伺服器回傳真正的 IP，解析器把答案快取一段時間。

> DNS 是整個網際網路的隱形基礎，也是最常被攻擊的目標之一。之後在 blue-02-logging-siem 與 blue-03-threat-intel 會看到 DNS 如何被濫用、又如何被偵測。現在先記住：DNS 的工作就是「名字 → 地址」的翻譯。

## IP 與 TCP：地址與送達保證

拿到 IP 之後，你的電腦要跟那台伺服器建立連線。這裡有兩層，各司其職：

* **IP（Internet Protocol）**：負責「定址與轉送」。每台連網設備都有一個 IP，像是郵件上的地址。IPv4 長這樣 `93.184.216.34`，因為數量快用完，世界正逐步改用更長的 IPv6。
* **TCP（Transmission Control Protocol）**：負責「可靠的送達」。它把資料切成小段、編號、送出，對方收齊後回報；缺了就重送。網頁內容不能掉，所以 Web 用的是 TCP，而不是不保證送達的 UDP。

| 特性 | IP | TCP |
|---|---|---|
| 角色 | 找到設備 | 確保資料完整到達 |
| 比喻 | 信封上的地址 | 掛號信的回執 |
| 負責 | 定址、路由 | 切割、編號、重送 |
| 使用它的服務 | 所有網路 | HTTP、SSH、Email |

`net-01-network-fundamentals` 會把這層拆得更深，包括封包怎麼在路由器之間跳動。

## Port：同一個地址，不同的門

一台伺服器同時提供好多服務：網站、SSH、Email。IP 找到了「這棟大樓」，但還要知道「哪一間房」。Port（埠）就是那扇門的編號。

重點是記住幾個常見埠，資安文章幾乎天天出現：

| 埠號 | 服務 | 加密 | 資安文章為什麼常提到它 |
|---|---|---|---|
| 22 | SSH 遠端管理 | 加密 | 伺服器的後門鑰匙，掃描與暴破熱點 |
| 53 | DNS 查詢 | 特殊 | 全世界查名字都靠它，也常被濫用 |
| 80 | HTTP 網站 | 明文 | 正被 443 取代，但老舊網站還在用 |
| 443 | HTTPS 網站 | 加密 | 現今網站的預設入口，TLS 的舞台 |

> recon-03-scanning-nmap 會教你用掃描工具檢查「哪些門開著」。這些能力只該用在你自己的系統、CTF 實驗室與授權測試。未經授權掃描別人的電腦，在很多國家都是違法的。這本書始終是防禦與教育導向。

## HTTP：網頁的溝通語言

連線建立後，瀏覽器與伺服器用 HTTP 交談。它是一來一往的請求／回應：瀏覽器發出一封「請求」，伺服器回一封「回應」。

一封請求大概長這樣：

```http
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Cookie: session=abc123
```

* **第一行**：方法（GET）、路徑（/index.html）、版本（HTTP/1.1）。
* **Headers（表頭）**：一行行的「欄位：值」。`Host` 告訴伺服器你要訪問哪個網站，`Cookie` 帶著你的登入狀態。
* **Body（本文）**：GET 通常沒有；POST 表單送出時才放內容。

回應則長這樣：

```http
HTTP/1.1 200 OK
Content-Type: text/html
Set-Cookie: session=xyz789; HttpOnly

<html>...</html>
```

狀態碼用數字表達結果，資安文章裡你一定要認識幾個：

| 狀態碼 | 意思 | 資安意義 |
|---|---|---|
| 200 OK | 成功 | 一切正常 |
| 301/302 | 重新導向 | 可能被利用做釣魚或 redirect 攻擊 |
| 401/403 | 未登入／被拒絕 | 權限控制的直接反應 |
| 404 | 找不到 | 目錄窮舉時，回應不同就洩漏線索 |
| 500 | 伺服器錯誤 | 常伴隨注入攻擊的報錯 |

## Cookie 與 Session：伺服器怎麼記得你

HTTP 本身是無狀態的：每個請求都是獨立事件，伺服器不記得你是誰。為了解決這件事，出現了 Cookie。

* 伺服器在回應裡放 `Set-Cookie`，瀏覽器之後每次請求都自動帶回。
* 最常見的用途是 Session ID：一串隨機值，代表「你已登入」。
* 安全細節很多：`HttpOnly` 讓 JavaScript 讀不到、`Secure` 只允許 HTTPS 傳送、`SameSite` 防跨站請求。

`web-03-auth-session` 會把登入、Session、Cookie 與相關攻擊一次講清楚；`web-01-owasp-top10` 也把 Session 管理列為最重要的議題之一。現在先記住一句話：**Cookie 是伺服器認你的憑證，被偷走就等於被盜用。**

## HTTPS：把明文變成密文

上面講的 HTTP 全部是明文：中間任何一台路由器或惡意 WiFi 都能讀到內容。HTTPS 就是在 HTTP 外面加了一層 TLS 加密，讓內容變成密文。

* **URL 從 http:// 變 https://**，瀏覽器出現鎖頭圖示。
* 加密同時兼顧「機密性」（別人讀不到）與「完整性」（內容沒被竄改）。
* 伺服器用數位憑證證明「我是真的 example.com」，這就是信任的來源。

HTTPS 是整個現代 Web 安全的支柱，值得一整篇來講：`net-02-tls-https` 是這個系列的下一站，會深入 TLS 握手、憑證與常見攻擊。

#### Q: 你在瀏覽器輸入網址之後，DNS 負責做哪一件事？

* 把資料切成封包送出

* 把網域名稱翻譯成 IP 位址

* 加密瀏覽器與伺服器之間的訊息

* 決定網頁要用哪種狀態碼回應
