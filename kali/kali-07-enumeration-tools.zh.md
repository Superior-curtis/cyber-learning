# 列舉工具：gobuster / ffuf / nikto

> 📅 2026-08-05 · 使用教學
> 掃描告訴你「門開著」，列舉告訴你「門後有什麼」。gobuster、ffuf、nikto 是列舉階段最常用的三把工具。這篇帶你認識它們各自擅長什麼，並附上可直接上手的用法。

---

`recon-03-scanning-nmap` 教了你掃描——找出「哪些門開著」。但門開著之後，問題才剛開始：**門後有什麼？** 回答這個問題的階段叫 **列舉（enumeration）**，而列舉階段最常用的三把工具，就是這篇的主角：gobuster、ffuf、nikto。

> 授權提醒：這三把工具都只應使用於你自己的伺服器、CTF 靶機、或有授權的範圍。暴力列舉會送出大量請求，對未授權的目標使用就是掃描攻擊，在大多地方都違法。

## 列舉在做什麼

掃描看到的是「埠與服務」，列舉更進一步：**逐一問這些服務「你到底提供什麼」。** 對網頁伺服器來說，就是問：

* 這個網站有哪些目錄與檔案？
* 有哪些子網域？
* 伺服器軟體是什麼版本、有沒有已知問題？

答案構成「攻擊面」的細節——這正是 `cve-03-reading-a-cve` 判斷「該不該擔心」所需的輸入。

## gobuster：找目錄與子網域

gobuster 用**字典爆破**的方式，猜測伺服器上隱藏的目錄或子網域：

```
# 找網站上隱藏的目錄
gobuster dir -u http://127.0.0.1/ -w /usr/share/wordlists/dirb/common.txt

# 找子網域
gobuster dns -d example.test -w /usr/share/wordlists/dns.txt
```

原理很直白：拿一本「常見名稱」清單，逐個去問伺服器「你有沒有這個路徑」。有回應，就代表路徑存在。對防守方而言，這也提醒你：**那些「以為沒人知道」的目錄，字典裡很可能早就列著。**

## ffuf：快速模糊測試

ffuf（fuzz faster you fool）是目前最快的模糊測試工具。它比 gobuster 更通用——不只找目錄，還能測參數、找隱藏欄位：

```
# 對某個參數做變化測試
ffuf -u http://127.0.0.1/FUZZ -w /usr/share/wordlists/dirb/common.txt
```

差別在於 `FUZZ` 這個佔位符：ffuf 會把字典裡的每個詞，替換進 `FUZZ` 的位置，一次送出大量請求並快速彙整結果。速度是它的招牌，也代表**它產生的流量很大——更只能在授權環境使用。**

## nikto：網頁伺服器掃描

nikto 不猜路徑，而是**把已知的伺服器問題清單**拿來對照：

```
# 掃描一個網站，找出已知問題
nikto -h http://127.0.0.1
```

它會檢查伺服器軟體版本、已知的脆弱設定、不安全的檔案與目錄。定位比較像「體檢報告」——快速列出「你可能該看看的項目」，之後再用 Burp 或人工確認。

| 工具 | 擅長 | 一句話定位 |
|---|---|---|
| gobuster | 找目錄與子網域 | 字典爆破路徑 |
| ffuf | 參數與隱藏欄位 | 高速模糊測試 |
| nikto | 已知問題對照 | 伺服器體檢報告 |

## 怎麼搭配

一次典型的列舉流程：

#### 先掃描

用 nmap 確認開著的埠與服務（recon-03-scanning-nmap）。

#### 再列舉目錄

對網頁埠用 gobuster 或 ffuf 找出隱藏路徑。

#### 對照已知問題

用 nikto 快速看看伺服器有沒有已知的脆弱設定。

#### 深入驗證

對有興趣的發現，用 Burp（kali-04）或人工細看。

> 記住這個流程：掃描 → 列舉 → 對照 → 深入。 每一步都用前一步的結果縮小範圍，比盲目亂試有效得多。

#### Q: gobuster 與 ffuf 的共同原理是什麼？

* 修改伺服器的設定檔

* 用字典逐一替換目標位置並發送請求，找出存在的路徑或參數

* 攔截瀏覽器的請求

* 分析已經抓好的封包

> 💡 兩者都是字典驅動的列舉工具：把字典詞彙送進目標位置（路徑或參數），有回應就代表該項目存在。
