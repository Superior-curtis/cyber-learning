# SQLmap：自動化注入測試

> 📅 2026-08-05 · 深入研究
> 在 web-02 你學會了 SQL 注入的原理與防禦。sqlmap 是那套原理的「自動化版本」——一條指令就能對授權目標做注入偵測。但自動化越強，越需要在正確的場合使用。

---

`web-02-injection` 教了你 SQL 注入是怎麼發生的、以及「參數化查詢」這個標準防禦。現在換到工具面：**sqlmap** 把「偵測某個輸入點有沒有 SQL 注入」這件事自動化了。

> 授權與界線（必讀）：sqlmap 會對目標自動送出大量且可能造成破壞的請求。它只能用於你自己的系統、或你有書面授權的範圍。對未授權目標執行 sqlmap，就是自動化攻擊，在多數地方違法。

## sqlmap 是什麼

sqlmap 是一個開源的 **SQL 注入自動化偵測工具**。它做的事情，就是把你（在 `web-02` 學的）「手動測試某個參數有沒有注入」的過程，變成一行指令 + 自動化判斷。

它會自動：

* 偵測目標參數是否存在 SQL 注入。
* 判斷注入的類型與背後的資料庫。
* 在授權前提下，列舉資料庫結構或內容。

**它的價值與風險一體兩面**：自動化越強，越代表「不能亂用」。

## 基本用法

sqlmap 的入門用法只需要給它「一個有參數的網址」：

```
# 對某個 URL 參數做注入偵測（示意）
sqlmap -u "http://127.0.0.1/item?id=1" --batch

# 加上 --dbs 可以在確認注入後列舉資料庫（僅限授權）
sqlmap -u "http://127.0.0.1/item?id=1" --dbs
```

> 永遠先 --batch 加上「只做偵測」的心態。 對自己的靶機，先用最小參數確認「有沒有注入」，確認後再決定要不要更進一步。慢慢來，比一路梭哈安全得多。

## 為什麼它只是起點

sqlmap 能告訴你「這個輸入點有注入」，但**不能代替你理解問題**：

* 它告訴你「哪裡有洞」，不告訴你「為什麼」——真正的修復，需要你回去看程式碼與 `web-02-injection` 的參數化查詢。
* 自動化可能誤報或漏報，關鍵的判斷永遠要人工確認。
* 對防守方而言，**用 sqlmap 掃自己的網站**，就像用字典掃自己的密碼——先找到洞，才能補洞。

把 sqlmap 想成**金屬探測器**：它快速幫你圈出「這裡可能埋了東西」，但挖不挖、挖出來是什麼、怎麼處理，都需要你。

## 防禦對照

不管自動化工具多強，防禦的答案沒有變——就是 `web-02-injection` 那句話：**參數化查詢，讓輸入永遠是資料、不是語法。**

如果你已經用了參數化查詢，sqlmap 掃你也是徒勞；如果你沒有，sqlmap 會立刻告訴你。**所以防守方的正確姿勢是：自己先用工具掃一遍，確認防禦真的有效。**
