`blue-06-phishing-defense` 講了釣魚的防禦。現在認識攻擊側的那把「成名作」：**Social Engineering Toolkit（SET）**——Kali 裡最有名、也最有爭議的工具之一。

這篇只做兩件事：**講清楚它是什麼、它利用什麼心理邏輯；以及防守方該怎麼防。** 概念與防禦優先，不提供任何針對真實目標的操作步驟。

> 授權與界線（必讀）：SET 設計用來做有書面授權的社交工程測試——例如幫公司演練「員工會不會上鉤」。對真實個人做釣魚、竊取憑證，在多數地方都是犯罪。本書只解釋概念與防禦，不提供任何釣魚或憑證竊取的劇本。

## SET 是什麼

SET（Social-Engineer Toolkit）是一套**把社交工程模組化的框架**。傳統上「騙人」靠臨場發揮，SET 把常見的套路整理成可選的模組——例如：

* **魚叉式釣魚**：客製化的釣魚郵件。
* **憑證竊取網頁**（概念上）：偽裝的登入頁。
* **網頁攻擊向量**：把惡意內容包進看似正常的網頁。
* **Payload 投遞**：把惡意檔案藏進附件。

關鍵在於：**工具只是把「套路」標準化，真正被利用的是「人」。** 理解這點，你才會知道防禦該打在「人」身上。

## 為什麼「人」會被騙：心理邏輯

社交工程不駭系統，它駭的是**人的直覺**。最常被利用的心理觸發：

| 觸發 | 利用的是 |
|---|---|
| 權威 | 假冒主管、IT、銀行——人傾向服從權威 |
| 急迫 | 「帳號即將鎖定」——讓你不思考、快動作 |
| 親切/互助 | 假冒同事、客服——降低戒心 |
| 社會認同 | 「大家都這麼做」——從眾 |
| 好奇 | 「免費」、「獨家」——勾起點擊慾望 |

> 這些觸發你早在 blue-06-phishing-defense 見過。 SET 的「貢獻」不是發明這些套路，而是把它們變成標準化、可重複的流程——所以防守方更要把「辨識觸發」練成肌肉記憶。

## 授權測試的正確用法

在合法、授權的場合，SET 這類工具的正確角色是**「內部演練」**：

* 公司僱用授權的測試方，模擬釣魚，量測「有多少員工會上鉤」。
* 結果用來**調整訓練與防禦**，而不是懲罰員工。
* 一切在書面授權範圍內，對象是自家人。

這跟 `lab-03-ctf-101` 的倫理同一條線：**受控的模擬 ≠ 攻擊真實目標的許可。**

## 防守方該怎麼防

SET 不管多會「模組化」，防守的答案沒有變——而且恰好是 `blue-06-phishing-defense` 那一整套：

* **人的訓練**：讓員工認得出權威/急迫/好奇這些觸發。
* **MFA**：就算憑證被騙走，多一道鎖（`pass-04-defenses`）。
* **郵件過濾與網址檢查**：攔下大部分釣魚信。
* **通報文化**：把「收到可疑信 → 通報」變成被鼓勵的事。
* **最小權限**：就算被入侵，損傷範圍有限。

> 最重要的防禦心態：攻擊者打的不是「系統」，是「人」。 所以最有效的防禦也不是「更硬的系統」，而是「更有意識的人」。別把 blue-06-phishing-defense 當成可有可無——它是對抗 SET 這類工具的第一道，也是最有效的一道防線。

* 伺服器的漏洞

* 人的直覺與心理觸發——權威、急迫、好奇等

* 防火牆設定

* 作業系統的密碼
