> 安全說明（HOMELAB ONLY）：本頁所有指令只對你自己的 homelab 網路與伺服器執行。對任何真實或第三方目標掃描，在多數地方都是違法行為——即使只是「看看開了哪些埠」。

## 安裝

```bash
sudo apt install nmap
nmap --version
```

## 主機發現

先找到「網段上有誰」——掃描的第一步，通常用 `-sn`（只做 ping，不掃埠）：

```bash
# 發現網段上存活的主機（只 ping，不快掃）
nmap -sn 192.168.1.0/24
```

這一步在 homelab 的意義：**盤點你自己網路上的裝置**，找出「多了誰」——未知裝置往往是警訊。

## 掃描手法

知道「誰在」，接著問「開了哪些門」：

```bash
# SYN 半開掃描（快速、最常用，需 root）
sudo nmap -sS -p- 192.168.1.10

# TCP 連線掃描（不需 root，較慢）
nmap -sT -p 22,80,443 192.168.1.10

# UDP 掃描（很慢，只對特定埠）
sudo nmap -sU -p 53,161 192.168.1.10
```

**SYN 掃描（-sS）是預設首選**：它只送 SYN、看回應，不完成握手，快又相對低調。`-p-` 掃全部 65535 個埠。

## 服務與版本辨識

`net-01-network-fundamentals` 說「埠是門」——`-sV` 則告訴你「門後是什麼服務、什麼版本」：

```bash
# 版本 + 預設腳本 + OS 偵測（常用的「全套」掃描）
sudo nmap -sV -sC -O 192.168.1.10
```

**版本辨識是 CVE 判斷的輸入**：掃到 `apache 2.4.49`，你才有辦法去 `cve-03-reading-a-cve` 或 `kali-10-exploitdb-searchsploit` 查它有沒有已知問題。

## NSE 腳本：nmap 的「外掛」

nmap 的強大，一半在 **NSE（Nmap Scripting Engine）**——內建數百個腳本：

```bash
# 列出所有腳本
ls /usr/share/nmap/scripts/

# 對某個服務跑特定腳本（例：網頁標題）
nmap -p 80 --script http-title 192.168.1.10

# 用安全等級跑一組常用腳本
sudo nmap -sV --script=vuln 192.168.1.10
```

> NSE 讓 nmap 從「掃描器」變成「偵察工具箱」：--script=vuln 這類腳本能對你自己的主機做初步的已知漏洞檢查——把「盤點」推進到「評估」。

## 輸出格式

掃描結果值得保存——`-oA` 一次輸出三種格式：

```bash
# 一次輸出普通/可 grep/XML 三種格式
sudo nmap -sV -oA lab-scan 192.168.1.10
```

保存下來，才能 `blue-02-logging-siem` 那套「先有基線」的思維——**你知道正常長什麼樣，才知道異常在哪。**

#### Q: nmap 的 `-sV` 參數主要在做什麼？

* 加快掃描速度

* 辨識埠背後的服務與版本——這是查已知漏洞（CVE）的輸入

* 隱藏掃描行為

* 直接執行漏洞利用

> 💡 -sV 辨識服務與版本，讓你能把『開了什麼』對應到『有沒有已知漏洞』；這是偵察到評估的關鍵一步。
