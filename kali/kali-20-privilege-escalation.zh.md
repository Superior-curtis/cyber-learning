# 提權：從低權限到 root 的邏輯與防禦

> 📅 2026-08-05 · 深入研究
> 滲透測試走到一半，你常常只有「低權限」。提權（privilege escalation）就是利用設定錯誤或漏洞，把權限往上推——從一般使用者到 root。這篇講透路線、homelab 指令與藍隊防禦。

---

滲透測試的流程，常常不是「一次到 root」，而是：**先拿到低權限 → 再想辦法往上推。** 這個「往上推」的階段，就是**提權（privilege escalation, privesc）**。

> 安全說明（HOMELAB ONLY）：本頁所有指令只在你自己的 homelab 主機（例如 Metasploitable，lab-02-vulnerable-targets）上練習。對真實系統提權，就是攻擊。

## 提權在做什麼

提權的目標一句話：**從「一般使用者」變成「root（或管理員）」**。為什麼重要？

* 低權限能開的門有限；root 幾乎能開所有門。
* 滲透測試的終點，常常是「證明我能拿到最高權限」——不是真的動手，而是**證明該修了**。
* 對防守方而言，理解提權 = 理解「為什麼最小權限與打補丁這麼重要」。

## 為什麼「低 → root」有可能

root 明明該是最難拿的，為什麼常常能靠「往上推」拿到？因為系統裡有幾個常見的「階梯」：

| 階梯 | 發生什麼 |
|---|---|
| sudo 設定太寬 | 普通使用者能「以 root 執行」某些程式 |
| SUID 檔案 | 某些程式以「擁有者的權限」執行，且可被利用 |
| 弱服務 | 以 root 跑的服務有漏洞或被濫用 |
| 未修補漏洞 | 核心/程式有已知提權漏洞（`cve-*`） |
| 過度可寫的檔案 | 能被寫入的設定檔，之後被 root 執行 |

> 記住共同點：提權幾乎總是利用「權限給太寬」或「該修的沒修」。 每一條階梯，都對應一個防守方該關的洞。

## homelab 指令（只限自己的主機）

在你自己的 homelab 主機（例如 Metasploitable）練習，先「把自己變成低權限使用者」，再開始偵察：

```bash
# 看看我這個使用者能用 sudo 跑什麼（homelab only）
sudo -l

# 找 SUID 檔（homelab only）
find / -perm -4000 -type f 2>/dev/null

# 跑自動化列舉腳本 linpeas（homelab only）
./linpeas.sh
```

> 安全說明（再次強調）：這些指令在你的 homelab 靶機上是在「練習防守課」；在真實系統上，就是未授權的提權攻擊。差別永遠在於你有沒有權限碰這台機器。

## 藍隊防禦

提權的每一條階梯，都有一把對應的鎖：

| 階梯 | 防守 |
|---|---|
| sudo 太寬 | `sudoers` 最小化：只給「需要的命令」，不給 `ALL` |
| SUID | 移除不必要的 SUID 位元、定期稽核 |
| 弱服務 | 不讓服務以 root 跑、最小權限（`blue-01-hardening`） |
| 未修補漏洞 | 打補丁（`cve-06-patch-management`） |
| 可寫檔案 | 正確的檔案擁有者與權限（`linux-03-permissions`） |

> 防禦心法：提權的根源是「過度權限 + 未修補」。 把最小權限與補丁做到位，攻擊者就算進得來，也爬不上去——blue-01-hardening 就是這套的完整版。

## 安全說明

* ✅ 可以：在**你自己的 homelab 靶機**上練習提權流程，驗證並理解防禦。
* ❌ 不可以：對任何真實或未授權的系統提權。
* ⚠️ 記住：未授權提權就是入侵；而在防禦完善的系統上，這個階段應該「推不上去」——那才是你該驗證的。

## 下一步

提權的邏輯與防禦清楚了。想從「系統加固」這端把它徹底關死，`blue-01-hardening` 是最佳章節；想複習權限本身的機制，`linux-03-permissions` 與 `linux-04-users-groups` 打底。

#### Q: 為什麼「權限給太寬」是提權最常見的根源？

* 因為 root 密碼太弱

* 因為系統預設會給普通使用者 root 權限

* 因為 sudo 太寬、SUID 太多、服務以 root 跑——每一條都讓低權限使用者能借用更高權限

* 因為防毒軟體沒開

> 💡 提權階梯（sudo 過寬、SUID、root 服務、未修補）本質上都是『過度權限 + 未修補』；防守把最小權限與補丁做好，攻擊者就推不上去。
