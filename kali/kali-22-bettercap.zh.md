# bettercap：中間人框架

> 📅 2026-08-05 · 深入研究
> bettercap 是把『中間人』模組化的框架——ARP 欺騙、嗅探、注入，一把工具全包。這篇講透它的邏輯、homelab 指令，以及藍隊怎麼防 ARP 欺騙。

---

`kali-19-responder-mitm` 講了中間人的概念。現在認識那把「MITM 界的瑞士刀」：**bettercap**——把中間人攻擊的各種手法（ARP 欺騙、嗅探、注入）模組化成一組工具。

> 安全說明（HOMELAB ONLY）：bettercap 的一切用法，只限你自己的 homelab 網段、你自己的裝置。在真實或他人的網路上做 ARP 欺騙，就是中間人竊聽——犯罪。

## bettercap 是什麼

bettercap 是一套開源的**中間人框架**。它把「站到資料流中間」這件事拆成模組：

* **ARP 欺騙**：讓網段上的裝置以為「攻擊者的 MAC = 閘道」，把流量導向攻擊者。
* **嗅探**：抓取經過的明文資料。
* **注入**：在轉送的流量裡注入內容。
* **DNS 欺騙**：把名稱解析導到假目標。

它把 `kali-19` 講的那些手法，變成「選單化」的框架。

## ARP 欺騙的邏輯

在交換式網路上，裝置預設只會把資料送給「它以為是閘道的那台」。ARP 欺騙做的就是**騙這個「以為」**：

1. 裝置要送資料給閘道 → 先查 ARP：閘道的 MAC 是誰？
2. 攻擊者**搶答**：「閘道的 MAC 是我」。
3. 裝置把資料送給攻擊者 → 攻擊者再轉送給真閘道。

> 記住這句：ARP 欺騙騙的是「路由的信任」，不是「加密」。 明文流量會被看光；加密流量（HTTPS/SRTP）騙到了也只是亂碼——所以加密是對抗 MITM 的基石。

## homelab 指令（只限自己的網段）

在你自己隔離的 homelab 網段、對你自己網段的裝置做「通訊演練」：

```bash
# 安裝
sudo apt install bettercap

# 在你自己網段的介面上啟動，並對自己的兩台測試機做 ARP 欺騙演練
sudo bettercap -iface eth0
# bettercap> set arp.spoof.targets 192.168.1.5,192.168.1.6   ← 你自己的測試機
# bettercap> arp.spoof on
```

在 homelab 的意義：**驗證「如果網段上有一台惡意機器，流量會不會被導走」**——這是防禦演練，不是攻擊。

> 安全說明（再次強調）：把 arp.spoof.targets 設成任何不是你自己網段的裝置，就是中間人竊聽——嚴重犯罪。homelab 演練做完，立刻 arp.spoof off。

## 藍隊防禦

| 措施 | 做法 |
|---|---|
| ARP 靜態綁定 | 閘道與重要主機用靜態 ARP，拒絕搶答 |
| 交換器安全 | 埠安全、動態 ARP 檢查（DAI） |
| 加密 | HTTPS/SRTP 讓騙到的流量只是亂碼（`net-02-tls-https`） |
| 監控 | 異常 ARP 廣播、閘道 MAC 變更偵測（`blue-02`） |

> 最高防禦心態：ARP 欺騙能騙「路由」，騙不了「加密」。 所以藍隊最強的一招不是「防 ARP」，而是「讓所有流量都加密」——騙到了也讀不懂。

## 安全說明

* ✅ 可以：在**你自己的 homelab 網段**，對**你自己的裝置**做上述演練。
* ❌ 不可以：對任何真實或他人的網段做 ARP 欺騙或竊聽。
* ⚠️ 記住：中間人竊聽是犯罪；而加密能讓它「騙到了也沒用」。

#### Q: ARP 欺騙騙的是什麼？

* 加密演算法

* 路由的信任——讓裝置把流量送給攻擊者；但它騙不了加密，加密流量被騙到也只是亂碼

* 使用者的密碼

* 防火牆規則
