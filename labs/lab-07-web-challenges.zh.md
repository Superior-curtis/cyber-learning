Web 是 CTF 最常被出題的類型，也是這本書著墨最多的領域之一——`web-01` 到 `web-05`、`kali-04`、`kali-07`、`kali-09` 全都在為這類題鋪路。現在把它們用起來。

> 授權提醒：Web 題的「靶子」是主辦單位提供的、受控的網站。解題技巧只屬於這些題目；用在真實的、你沒有授權的網站上，就是違法。

## Web 題在做什麼

Web 題給你一個**刻意有漏洞的網站**，要你利用它的缺陷找到旗標。它不是要你「破解整個網站」，而是通常**一個題目 = 一種漏洞**：

* 這題考 SQL 注入？那某個輸入點就是關鍵。
* 這題考權限？那某個「以為沒人看得見」的頁面就是入口。
* 這題考 Cookie？那身分管理一定有破綻。

題目往往只要求你「找到那個破綻，並用它拿到旗標」——範圍小、目標明確。

## 起手式

| 動作 | 用什麼 |
|---|---|
| 看頁面與程式碼 | 瀏覽器的開發者工具（DevTools） |
| 看請求與回應 | Burp Suite（`kali-04-burp-suite`） |
| 找隱藏路徑 | gobuster / ffuf（`kali-07-enumeration-tools`） |
| 測注入 | 手動 + sqlmap（`kali-09-sqlmap`） |

> Web 題的第一步永遠是「偵察」：先看頁面原始碼、看 Cookie、看請求結構，再決定攻擊角度。recon-01-recon-osint 的心法在 Web 題裡同樣適用——先看清楚，再動手。

## 常見考點

| 考點 | 線索 | 對應知識 |
|---|---|---|
| 參數操控 | 改 URL 或表單參數有不同結果 | `web-02-injection` |
| Cookie 篡改 | 改 Cookie 改變身分 | `web-03-auth-session` |
| 權限繞過 | 某些路徑「本該被擋」 | `web-01-owasp-top10` A01 |
| 隱藏功能 | 程式碼或目錄裡藏著入口 | `kali-07-enumeration-tools` |
| SSRF/CSRF | 請求被操控 | `web-04-ssrf-csrf-upload` |

## 練習心法

* **先看原始碼**：很多 Web 題的提示就寫在 HTML 註解或 JS 裡——「看原始碼」永遠是低成本高報酬的第一步。
* **一次改一個變數**：改參數、看回應、再改——像 `kali-04-burp-suite` 教的 Repeater 循環，用最小步進找出規律。
* **對照知識**：卡住時，問「這像 `web-02` 的哪個概念？」——題目設計出來就是為了對應某個章節。
