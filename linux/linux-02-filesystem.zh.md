# 檔案系統與目錄結構

> 📅 2026-08-05 · 使用教學
> 在 Linux 裡，所有檔案都住在一棵從根長出的樹上。看懂 /etc、/var、/home、/tmp 各自的位置，你就知道證據、設定與可疑檔案分別該往哪裡找。

---

在 Windows 裡，你的檔案住在 C 槽、D 槽這些盤符裡；在 Linux 裡，**所有的檔案都住在一棵樹上，從 `/` 這個根長出來。**這不是文字遊戲——這是你在走進任何一台伺服器之前，第一個要建立的地圖。而且對資安來說，這張地圖直接告訴你：**證據在哪裡、設定在哪裡、可疑的檔案該往哪裡看。**

這篇文章會教你認路。老手每天都在用的幾個小工具（`pwd`、`ls`、`cd`、`find`）一次配齊，最後把「目錄位置」和「資安直覺」接在一起。

## 一切皆檔案，從根長出一棵樹

Linux 的哲學是「**一切皆檔案**」：普通文件是檔案、目錄是檔案、連你的硬碟、正在跑的程式、鍵盤輸入，都被當成檔案來看待。而所有這些檔案，被整齊地掛在一棵倒過來的樹上。

這棵樹的頂端是**根目錄 `/`**。從根往下分出各種目錄，每一層都是「路徑」的一步。例如 `/etc/ssh/sshd_config`，意思是：從根（`/`）進到 `etc`，再進到 `ssh`，最後是 `sshd_config` 這個檔案。

和 Windows 最大的差別是：**沒有「磁碟機代號」這種東西。**一個硬碟、一支隨身碟、一片網路掛載，都可以被「掛載」到這棵樹的任何一個目錄底下。對使用者來說，一切都只是樹上的路徑。

## 掛載：沒有 C 槽的世界

因為沒有盤符，「接上新裝置」在 Linux 裡有另一個詞：**掛載（mount）**。一支 USB、一顆新硬碟、一片網路磁碟，都要被掛到這棵樹的某個目錄上，例如 `/mnt/usb`。掛載點是「樹上的空位」，掛上去之後，路徑就通到那個裝置裡。

對你（未來的資安人員）而言，這有個務實的好處：**你不需要知道「資料在哪一顆實體硬碟」，只需要知道路徑。**遇到一台陌生機器，`mount` 指令會告訴你每個掛載點對應什麼裝置——而「有奇怪的東西被掛到奇怪的地方」，本身就可能是異常訊號。掛載的概念在後面談服務與隔離時（例如 `linux-05-processes-services`）會一再回來。

## 你該認識的目錄

你不用把所有目錄都背下來，但下面這幾個是資安工作者天天會碰到的地標，值得先記住：

| 目錄 | 用途 | 資安上的意義 |
|---|---|---|
| `/` | 樹根，一切從這裡開始 | 所有路徑的起點 |
| `/etc` | 系統設定檔的家 | **弱點與設定錯誤大多住在這裡** |
| `/var` | 會變動的資料：日誌、佇列、快取 | **日誌（`/var/log`）是事件調查的起點** |
| `/home` | 每個使用者的個人資料夾 | 使用者的檔案、`~/.ssh` 金鑰 |
| `/tmp` | 人人可寫的暫存區 | 常見的可疑檔案藏身處（下一章的主角） |
| `/usr` | 安裝的程式與函式庫 | 系統執行的本體 |
| `/bin`、`/sbin` | 可執行程式 | 系統開機就要用到的指令 |

重點不是一次記住全部，而是先有「每個東西都有自己該待的地方」這個感覺。資安的一個核心直覺就是：**當一個檔案出現在不該出現的地方，或一個設定檔有了它不該有的內容，事情就不對了。**

## 隱藏檔案：檔名開頭的那一點

Linux 有個奇怪的小規則：**檔名以 `.` 開頭的檔案預設被「藏起來」**——`ls` 不會顯示，要用 `ls -a` 才看得到。這些「點檔案」不是為了資安（只是歷史慣例），但它們常常放著重要的東西：

| 點檔案 | 通常是什麼 |
|---|---|
| `~/.bashrc` | 使用者的 Shell 設定 |
| `~/.ssh/` | SSH 金鑰與設定（整個目錄都是點目錄） |
| `~/.profile` | 登入時的環境設定 |

資安上的兩層意義。第一，**想完整看一個目錄，記得 `ls -a`**——漏掉點檔案就漏掉一半線索；第二，攻擊者很喜歡把工具或後門藏在點檔案裡，因為預設看不到。`linux-07-logs-auditing` 與 `linux-08-networking-cli` 會用到這個直覺。

## 絕對路徑與相對路徑

在樹裡指路，有兩種方式：

* **絕對路徑**：從根開始寫完整路線，開頭一定是 `/`。例如 `/var/log/auth.log`。
* **相對路徑**：從「你現在所在的位置」開始。例如你已經在 `/var` 裡，寫 `log/auth.log` 就好。

這就像是：「我家在中山路 10 號」（絕對）對比「出了門右轉第二條巷子」（相對）。兩種都常用，但**用錯會讀到錯誤的檔案**——這不是文書上的小事，而是一個經典的組態錯誤來源：程式用相對路徑，結果在不同的工作目錄下啟動，讀到的設定檔完全不一樣。

## 捷徑：符號連結

Linux 的「捷徑」叫**符號連結（symbolic link，symlink）**：一個檔名只是「指向另一個檔案」。建立方式是 `ln -s 目標 連結`，之後讀這個連結，等於讀目標。

```
ln -s /etc/nginx/nginx.conf /tmp/web_config
```

符號連結在資安上有兩面。正常的用途：把設定、程式連結到方便的位置，省得複製一份。危險的用途：**如果一個高權限的程式跟著連結去讀寫檔案，攻擊者就能把連結「重新指向」自己想要的檔案**——經典的「符號連結競態」漏洞（symlink race）就是這樣。安全的做法很簡單：寫入檔案前先檢查它是不是連結，並對 `/tmp` 這類人人可寫的目錄保持警覺。

`ls -l` 會用 `l` 標示符號連結，並在名稱旁顯示 `->` 指向哪裡。

## 走動與尋找：你的第一組指令

現在動手。開啟你的終端機（或任何一台 Linux 主機），用這幾條指令建立肌肉記憶：

| 指令 | 做什麼 |
|---|---|
| `pwd` | 印出「現在在哪裡」（Print Working Directory） |
| `ls` | 列出目前目錄的內容 |
| `cd /etc` | 移動到 `/etc` |
| `cd ..` | 往上層移動一層 |
| `cd ~` | 回到自己的家目錄 |
| `find / -name "*.conf"` | 從根開始，找出所有 `.conf` 檔 |
| `locate sshd` | 用索引快速搜尋（先跑過 `updatedb` 才有索引） |

`find` 是真正的瑞士刀：它不只找名字，還能按大小、時間、權限、擁有者過濾——後面的章節你會用它，在**你自己的測試機器或 CTF 環境**裡翻找可疑檔案。`locate` 很快但依賴索引，適合日常找檔，不夠靈活。

```bash
pwd
# /home/tom
ls
# Desktop  Documents  notes.txt
cd /var/log
ls | head
# auth.log  boot.log  dmesg  syslog  ...
pwd
# /var/log
```

注意看：`cd /var/log` 之後，`pwd` 的回答就變了。**你在哪個目錄，決定了「相對路徑」指向哪裡**——而這正是很多設定錯誤的來源，也是你在別人的文件裡看到「照著做卻沒用」時的第一個檢查點。

再進階一點，`find` 可以按「不是名字」的條件找東西：

```bash
# 在 /etc 找最近三天內被改過的設定檔
find /etc -name "*.conf" -mtime -3

# 找所有人都可寫的檔案（風險訊號）
find / -type f -perm -0002 2>/dev/null

# 找大於 100MB 的檔案
find /home -size +100M
```

`-mtime -3` 是「三天內改過」，`-perm -0002` 是「其他人可寫」。這幾招在 `linux-09-hardening-basics` 的稽核清單裡會反覆出現——先留個印象。

## 這對資安為什麼重要

「檔案住在哪」在資安上不是細節，而是證據線索。三條最實用的線索：

* **`/etc` 是設定檔的家。** 想檢查一台機器有沒有被改設定、有沒有開奇怪的服務，先逛 `/etc`。
* **`/var/log` 是事件紀錄的家。** 誰登入過、什麼時候失敗過、程式有沒有崩潰，全部在這裡。`linux-07-logs-auditing` 會教你怎麼讀。
* **`/tmp` 是「人人可寫」的。** 任何使用者都能在 `/tmp` 建立檔案，這使它成為攻擊者很愛藏東西的地方——也是下一章權限的主角。

一旦你習慣「用目錄想事情」，看到任何一台伺服器都不再是亂糟糟的一團。你腦中自然浮現那棵樹，以及每個地標該放什麼東西。

> 路徑就是一種語言。 讀懂 /var/log/auth.log 需要三種知識疊在一起：/var 代表「會變動的資料」、log 代表「日誌」、auth 代表「認證」。拆得開路徑，你就讀得懂機器在跟你說它做過什麼。

## 下一步

你現在知道每個檔案「住在哪」。下一章回答更尖銳的問題：**誰能讀、誰能寫、誰能執行**——權限與擁有者（`chmod`／`chown`）。那也是「為什麼 `/tmp` 人人可寫很危險」的正式答案。就是 `linux-03-permissions`。

#### Q: 一台 Linux 伺服器出了資安事件，你想查「誰在今天凌晨嘗試登入失敗」。第一站應該去哪裡？

* /etc 裡找登入設定

* /var/log 裡找認證相關的日誌

* /home 裡翻每個使用者的檔案

* /tmp 裡找暫存檔

> 💡 登入與認證事件被記錄在 /var/log 底下（例如 auth.log）。/etc 放設定、/home 放使用者資料、/tmp 是人人可寫的暫存區——都不是記錄登入嘗試的地方。
