# 權限與擁有者（chmod / chown）

> 📅 2026-08-05 · 使用教學
> Linux 的權限系統是整台機器最基本的門鎖：r、w、x 三種動作，套在擁有者、群組與其他人身上。設錯一組權限，就是一扇敞開的門。

---

電腦裡每一扇門都有一把鎖，而鑰匙分三種：你是誰、你屬於哪個群組、以及你是「其他所有人」。Linux 的權限系統就是這套門鎖——它是整台機器最基本的防線，也是資安上**最容易被設錯、又最常被利用**的地方之一。這篇文章把這套鎖徹底拆開，最後你會清楚看到「為什麼權限設錯本身就是一個漏洞」。

## rwx：三種動作

每一個檔案或目錄，都對三類人各定義了三種動作：

| 動作 | 對檔案 | 對目錄 |
|---|---|---|
| **r**ead（讀） | 可以看內容 | 可以列出裡面有什麼 |
| **w**rite（寫） | 可以改內容 | 可以新增或刪除裡面的檔案 |
| e**x**ecute（執行） | 可以當程式跑 | 可以「走進」這個目錄 |

「三類人」是**擁有者（user）**、**群組（group）**、**其他人（other）**。一個檔案的權限因此可以寫成三組 `rwx`，例如：

```
-rwxr-xr-x    tom   devs    program
```

從左到右拆開讀：

* `-`：它是普通檔案（若是 `d` 就是目錄）。
* `rwx`：**擁有者** tom 可以讀、寫、執行。
* `r-x`：**群組** devs 可以讀、執行，但不能寫。
* `r-x`：**其他人**可以讀、執行，但不能寫。

順序是固定的：`u`（user）→ `g`（group）→ `o`（other），每組三位 `rwx`。`ls -l` 印出來的第一欄就是這串符號。

## 讀懂 `ls -l` 的完整一行

權限字串是 `ls -l` 的第一欄，但整行還藏著更多資安資訊。拿這個例子：

```
-rwxr-xr-x  1 tom  devs  2048  Aug  5 10:30  program
```

欄位依序是：

| 欄位 | 例子 | 意思 |
|---|---|---|
| 類型與權限 | `-rwxr-xr-x` | 檔案類型（`-` 或 `d`）＋三組 rwx |
| 連結數 | `1` | 這個檔案有幾個名稱 |
| 擁有者 | `tom` | 誰擁有它 |
| 群組 | `devs` | 它屬於哪個群組 |
| 大小 | `2048` | 位元組 |
| 修改時間 | `Aug 5 10:30` | 最後一次被改的時間 |
| 名稱 | `program` | 檔名 |

對調查來說，「最後修改時間」常常是關鍵線索：**一個系統檔被改的時間點，往往就是事件發生的時間點。**養成掃一眼整行的習慣，你看到的就不再是「一串文字」，而是一台機器的時間軸。

## 數字模式：為什麼大家都說 755、644

符號好讀，但指令用數字。每個 `r`、`w`、`x` 對應一個數字，有就是 1、沒有就是 0：

```
r = 4    w = 2    x = 1
```

每組三位加起來，得到一個 0–7 的數字：`rwx` = 4+2+1 = 7，`r-x` = 4+0+1 = 5，`r--` = 4。三個數字湊在一起就是完整權限：

| 數字 | 展開 | 意思 |
|---|---|---|
| `755` | `rwxr-xr-x` | 擁有者可讀寫執行；其他人可讀可執行 |
| `644` | `rw-r--r--` | 擁有者可讀寫；其他人只能讀 |
| `600` | `rw-------` | 只有擁有者可讀寫——私密檔的標準 |
| `777` | `rwxrwxrwx` | 人人皆可讀寫執行——幾乎永遠不該出現 |

邏輯很樸素：**數字越大，能開的門越多。** `777` 等於把門鎖全拆了，極少檔案需要這種待遇。

```bash
# 把 script.sh 設為 755：自己可寫，其他人只能讀與執行
chmod 755 script.sh

# 把 secret.key 設為 600：只有自己可讀寫
chmod 600 secret.key

# 符號模式：替群組加上讀取權限
chmod g+r report.txt

# 把目錄內容一律設為 644
chmod -R 644 docs/
```

符號模式也很好用：`u`/`g`/`o` 搭配 `+`/`-` 與 `r`/`w`/`x`，例如 `chmod o-w file` 的意思是「拿掉其他人的寫權限」。

## chown：這扇門鎖歸誰管

權限是「鎖」，而**擁有者是「誰有權決定這把鎖」**——只有擁有者（或 root）能修改一個檔案的權限，或把它轉交給別人。改擁有者用 `chown`：

| 指令 | 效果 |
|---|---|
| `chown tom file` | 把 file 的擁有者改成 tom |
| `chown tom:devs file` | 同時改擁有者 tom 與群組 devs |
| `chown -R tom:devs docs/` | 遞迴處理整個目錄 |

大部分時候你不太需要動 `chown`，但它是權限故事的必要一半：**權限設得再嚴，擁有者設錯，等於把鑰匙交給錯的人。**

## umask：新檔案一出生就有的權限

新檔案「出生」時會有一個預設權限，由 **umask** 決定。umask 是「扣除值」：`umask 022` 的意思是「預設扣掉『其他人寫入』這個位元」，所以：

* 新檔案：`666 - 022 = 644`（`rw-r--r--`）
* 新目錄：`777 - 022 = 755`（`rwxr-xr-x`）

你可以在 `~/.bashrc` 或系統設定裡改 umask。**太寬鬆的 umask 會讓每個新檔案預設人人可寫**——這類「預設太鬆」的問題，正是資安稽核最常抓的項目之一。

常見的 umask 值與它們的效果：

| umask | 新檔案 | 新目錄 | 嚴謹程度 |
|---|---|---|---|
| `022` | `644` | `755` | 常見預設：其他人可讀 |
| `027` | `640` | `750` | 群組可讀，其他人看不見 |
| `077` | `600` | `700` | 最私密：只有自己能碰 |

多數情況 `022` 就夠用了。但如果這台機器存放敏感資料（金鑰、密碼檔、客戶個資），把 umask 收到 `077`，讓「新檔案預設只有自己可讀」成為常態，是成本極低的一層保護。

## sticky bit：把 /tmp 變成交往的公共客廳

`/tmp` 必須「人人可寫」，但也因此**任何使用者都能刪掉別人的暫存檔**——在共用主機上這是場災難。解法叫 **sticky bit**，權限的最後一碼會顯示為 `t`：

```
drwxrwxrwt   /tmp
```

開了 sticky bit 的目錄，允許所有人建立檔案，但**只有檔案的擁有者（或 root）能刪除它**。這正是 `/tmp` 在真實系統上的長相。當你在 `ls -l` 的結尾看到 `t` 或 `T`，就是它。

## 資安意義：誰能寫，誰就能換掉內容

把整套機制疊起來，權限的資安意義只有一句話：**權限管的是「誰能改這台機器上的什麼」——而這正是攻擊者最想拿到的東西。**幾個經典問題：

| 問題 | 為什麼危險 | 防禦 |
|---|---|---|
| 設定檔是 `777` | 任何使用者都能改系統設定 | 改成 `644` 或更緊 |
| 程式碼目錄人人可寫 | 攻擊者可塞入惡意內容，等系統執行 | 移除 group/other 的寫權限 |
| 私密金鑰是 `644` | 其他使用者讀得到你的 `~/.ssh/id_rsa` | 改成 `600` |
| `/tmp` 沒有 sticky bit | 任何人可刪別人的暫存檔，破壞證據 | 確認 sticky bit 存在 |

反過來想，你就能理解為什麼**不當的權限本身就是一整個漏洞類別**：OWASP 的「不安全的存取控制」、CVE 清單裡一整櫃的「預設權限過寬」，都是同一個主題。防禦的原則很樸素——**最小權限：只給需要的人、剛好夠用的權限。**稽核時用 `find / -perm 777` 或 `ls -l` 掃一遍，你馬上就知道這台機器把哪幾扇門敞開著。

## 權限稽核實務：十分鐘的掃描

把這章的知識變成行動，幾個指令就是一次小型稽核：

```bash
# 找全世界都可寫的檔案
find / -perm -0002 -type f 2>/dev/null

# 找設定目錄底下過寬的權限
find /etc -perm -002 -type f 2>/dev/null

# 看看你的金鑰是否人人可讀
ls -l ~/.ssh/
```

掃出結果之後的判斷很樸素：**它真的需要這樣嗎？** 如果不需要，就把它收緊——`chmod` 三秒鐘的事，卻能關掉一扇別人計畫要走的門。`linux-09-hardening-basics` 會把這套掃描擴大成完整的加固流程。

> 權限不是「設定細節」，是「邊界」。 一個只有 root 能讀的設定檔、一把只有自己能讀的金鑰、一個沒人能寫的目錄——這些安靜的 600、755，才是防禦真正落地的位置。檢查一台系統是否安全，先檢查誰能寫。

權限的「三類人」裡，最關鍵的問題是：**誰算「使用者」、誰算「群組」？** 下一章進入使用者的世界——帳號、群組、root、sudo，以及「為什麼絕不用 root 做日常操作」。就是 `linux-04-users-groups`。

#### Q: 你的私密 SSH 金鑰（~/.ssh/id_rsa）顯示的權限是 644，也就是 rw-r--r--。你該怎麼做？

* 不用管，因為金鑰不是設定檔

* 把它改成 600，讓只有自己可讀寫

* 把它改成 777，方便任何程式讀取

* 把它移到 /tmp，因為那裏人人可寫

> 💡 私密金鑰等同你的身分，644 表示同一台機器上的其他使用者都能讀取。改成 600（rw-------）是標準做法，讓只有自己碰得到它。
