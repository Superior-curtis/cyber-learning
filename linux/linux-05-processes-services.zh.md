# 程序、服務與 systemd

> 📅 2026-08-05 · 使用教學
> 每一台 Linux 機器，都是幾百個同時運作的程式的集合。學會看程序、管理服務，你就學會了第一個藍隊技能：知道系統平常長什麼樣。

---

伺服器看起來很安靜——沒有視窗、沒有動畫、風扇只是微微轉。但在那個安靜的黑盒子裡，同時有幾百個程式在跑。這篇文章教你怎麼「看見」它們、管理它們，以及最重要的：**知道系統平常長什麼樣，是你抓出異狀的第一步。**

在 Linux 的世界裡，這些運作中的程式各自有名字：程序、服務、守護程序、行程。它們關係很近但意思不同。看懂之後，你就有了伺服器的「生命跡象」。

## 程序是什麼

一個**程序（process）**，是「一個程式被啟動之後、正在執行的那個實例」。你用同一支編輯器開三個視窗嗎？那是一個程式、三個程序。程式是磁碟上的檔案，程序是記憶體裡活著的東西。

每個程序都有身分：

| 名詞 | 全名 | 意思 |
|---|---|---|
| PID | Process ID | 系統給每個程序唯一的數字編號 |
| PPID | Parent PID | 這個程序是由誰啟動的 |
| UID | User ID | 這個程序以誰的身分執行 |

程序會「生孩子」：你啟動的程式會再啟動子程式，形成一棵家族樹。這棵樹很重要——一個陌生的程序，往上追它的父母，常常就能看出它從哪來。

```
systemd (PID 1)
 └── sshd ──── sshd ──── bash ──── ps
 └── nginx
```

## 用 ps 看程序

要替系統目前的所有程序「拍張照」，用 `ps`。最實用的寫法：

```bash
ps aux
```

`aux` 三個字母沒有什麼深意，記起來就好。它會印出很寬的一張表，重點欄位是：

| 欄位 | 意思 |
|---|---|
| `USER` | 這個程序以誰的身分執行 |
| `PID` | 程序編號 |
| `%CPU` `%MEM` | 吃了多少 CPU 與記憶體 |
| `COMMAND` | 實際執行的指令 |

`ps` 是快照——它顯示的是「按下去的瞬間」。要看到動態變化，往下看。

`ps aux` 的第一欄是 `USER`。把上一章連起來：**這欄告訴你這個程序以誰的身分執行。** 一個以 root 跑的網頁伺服器，跟一個以普通帳號跑的網頁伺服器，被入侵之後的破壞力完全不同。看程序，永遠順便看它的 USER——這是 `linux-04-users-groups` 最重要的應用時刻。

## 用 top / htop 即時監看

`top` 會開一個持續更新的畫面，按 CPU 使用率排序，每幾秒刷新一次。`htop` 是更好看的版本（可能要先裝）。資安上它的用途非常明確：**哪個程序在暴衝 CPU？哪個程序吃了整台機器的記憶體？**

「有一個程序突然把 CPU 吃滿」是常見的警訊。可能是正常的批次作業，也可能是有人在你的機器上挖礦。別急著殺，先看清楚它是什麼——這是接下來要講的關鍵習慣。

## 訊號與 kill：優雅地請程序離開

要結束一個程序，不能直接「刪掉」它——你要對它送一個**訊號（signal）**。最常用的是 `kill` 指令配上 PID：

```bash
kill 1234        # 送 SIGTERM，請程序優雅收尾
kill -9 1234     # 送 SIGKILL，直接強制結束
```

| 訊號 | 行為 | 何時用 |
|---|---|---|
| `SIGTERM`（預設） | 通知程序「該結束了」，讓它自己清理 | 平常優先使用 |
| `SIGKILL` | 系統直接結束它，程序無法抗拒或清理 | 程序卡死，SIGTERM 無效時 |

先送 SIGTERM，讓程序有機會儲存狀態、關閉檔案；無效才升級到 SIGKILL。**動手之前，先確認那個 PID 真的是你想殺的**——殺錯一個服務，比放過一萬個不要緊的程序都慘。

## 服務與 systemd

不是每個程式都該被手動啟動。有些程式是設計來**常駐背景、替整個系統服務**的——這些叫**服務（service）**或**守護程序（daemon）**：網頁伺服器、資料庫、SSH、排程器，都是。

現代 Linux 用 **systemd** 管理它們。systemd 是開機後第一個跑起來的程序（PID 1），負責啟動、監督、重啟所有服務。跟它互動的指令是 `systemctl`：

```bash
sudo systemctl status sshd     # 這個服務現在怎麼樣
sudo systemctl start sshd      # 啟動
sudo systemctl stop sshd       # 停止
sudo systemctl enable sshd     # 設定開機自動啟動
sudo systemctl disable sshd    # 取消開機自動啟動
```

看到規律了嗎？`status / start / stop` 管的是「現在」，`enable / disable` 管的是「以後開機還要不要跑」。**這五個動詞是資安上最重要的幾個按鈕**——因為「停掉用不到的服務」是最便宜的攻擊面縮減。

> 值得一記的配對：`active / inactive` 描述「現在」，`enabled / disabled` 描述「開機」。一開機就自動跑的服務（enabled）才是真正的攻擊面；只在需要時才手動啟動的（disabled），風險小得多。

## 開機到底跑了什麼

「這台機器一開機，到底自動啟動了什麼？」這是防禦者永遠想知道的問題：

| 想看什麼 | 指令 |
|---|---|
| 目前開機已載入的服務 | `systemctl list-units` |
| 設為開機自動啟動的服務 | `systemctl list-unit-files --state=enabled` |
| 某服務最近的日誌 | `journalctl -u sshd` |

systemd 之外，也別忘了兩條老路：`cron` 排程表（`crontab -l`、`/etc/cron.*`），以及「現在真的在監聽網路的程序」（`ss -tlnp`）。開機自動啟動的每個東西，都是別人可以碰到的入口。

> 藍隊基本功：建立「正常」的基準線。 挑一台你信任的機器，把 systemctl list-unit-files --state=enabled 的輸出存下來。下次系統怪怪的，把輸出比一比——多出來的服務，就是你應該優先調查的對象。 你不需要先懂得一切，只需要能分辨「跟平常不一樣」。

## 面對陌生的程序：先調查，再行動

看到不認識的程序時，最危險的反應是慌張。正確的流程是：

#### 先看，不要先殺

用 ps aux 找出 PID，再用 ps -fp \<PID> 看它的父程序與啟動者，判斷它從哪裡來。

#### 查日誌與設定

用 journalctl -u <服務名> 看相關日誌，用 grep 找設定檔，確認它是誰、為了什麼裝上去的。

#### 確認沒問題才動手

如果真的不需要它，先停用再取消開機自啟：sudo systemctl disable <服務>。

這套「先調查、後行動」的順序，就是事件處理的雛形。你在 `blue-04-incident-response` 會看到同樣的步驟被放大成整個團隊的流程。

## 資安該怎麼看程序

把這一章變成動作：

| 檢查 | 你想知道什麼 |
|---|---|
| `ps aux` 掃一圈 | 有沒有不認識的程序在跑 |
| `top` 看一輪 | 有沒有程序異常佔用 CPU |
| `ss -tlnp` | 哪些服務正在對外監聽 |
| `systemctl list-unit-files --state=enabled` | 哪些服務開機就在跑 |

「少即是好」是通用的原則：**服務越少，攻擊面越小。** 每多一個監聽的服務，就是多一個可能被利用的入口。停用用不到的服務、關掉不需要的連接埠——這是最沒有技術含量、也最有效的加固動作，也是 `linux-09-hardening-basics` 的第一課。

## 下一步

學會看程序之後，你的下一個工具是**快速在文字海裡撈東西**。`linux-06-shell-essentials` 教你一群實用指令——grep、find、管線——讓你把「幾百個程序」和「上萬行日誌」變成一行讀得完的答案。

#### Q: 系統突然變慢，top 顯示一個你不認識的程序吃掉了 99% 的 CPU。最安全的處理順序是什麼？

* 立刻用 kill -9 把它的 PID 殺掉，越快越好

* 先查清楚它是什麼（ps、看父程序、查日誌），確認有問題再處理

* 直接重開機，眼不見為淨

* 把所有程序的 PID 一次殺光，清得乾乾淨淨

> 💡 先調查、後行動。不認識的程序可能是警訊也可能只是誤判，亂殺 PID 可能殺掉重要的服務。先用 ps 與日誌弄清楚它從哪裡來，再決定怎麼處理。
