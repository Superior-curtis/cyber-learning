# 命令列網路工具（ip / ss / ports）

> 📅 2026-08-05 · 使用教學
> 用命令列回答三個網路問題：這台機器有哪些網卡、哪個埠在聆聽、它在跟誰講話。ip、ss、curl、dig、nc 的實用場景一次看懂。

---

## 三個問題，一套工具

網路出問題時，你最想問的就是三個問題：**這台機器長什麼樣？誰在門口等著服務？它現在在跟誰講話？** 好消息是，Linux 命令列早已把這三個問題的答案，全部變成幾條指令。

壞消息是，工具名字一堆，還分新舊兩代。這章不給你字典，只給你「遇到問題該敲哪條」的實戰地圖。我們會走過 `ip`、`ss`、`curl`、`dig` 與 `nc`，每一支工具都對應一個真實情境。

## ip：問網路卡的第一站

傳統的 `ifconfig` 已經逐步退場，現代的發行版都用 `ip` 指令。它負責「這台機器長什麼樣」：有哪幾張網卡、各自的 IP、有沒有起來。

```bash
# 列出所有網路介面與 IP
ip addr

# 只看簡潔版的介面狀態（UP 或 DOWN）
ip -br addr

# 看路由表：預設閘道往哪走
ip route
```

`ip addr` 是排錯的起點——先確認介面是 `UP` 還是 `DOWN`，再確認 IP 有沒有正確設定。網路不通時，這三條指令能在十秒內告訴你「問題在介面、IP 還是路由」。

## ss：哪個埠在聆聽？

「哪個服務開了哪個埠？誰正連著？」是資安與維運的每日問題。現代答案是 `ss`，取代了老牌的 `netstat`。**聆聽（LISTEN）**表示某個程式正在那個埠上等待連線——這正是「誰在門口開門」的答案。

```bash
# 所有正在聆聽的 TCP 埠，連同是哪個程式
sudo ss -tlnp

# 正在聆聽的 UDP 埠
sudo ss -ulnp

# 所有已建立的連線（含對方 IP）
ss -tn
```

加上 `-p` 能看到是哪個程序，這就是藍隊最愛用的「這個埠是開誰的門」查詢。老工具 `netstat -tlnp` 在同一個場景依然可用，只是部分發行版需要另外安裝。

**初學者最容易犯的錯**：只記埠號，不記得問「綁在哪張網卡」。一個服務若綁在 `0.0.0.0:22`，代表所有介面的 22 埠都對外；若綁在 `127.0.0.1:5432`，只有本機碰得到。前者常常是資料庫被掃描攻擊的原因——這點我們在下一章 `linux-09-hardening-basics` 會再回來談。

## 常用埠速查表

不需要背，但需要「看過有印象」：

| 埠 | 協定 | 服務 | 資安意義 |
|----|------|------|---------|
| 22 | TCP | SSH | 遠端登入，最常被暴力掃描的目標 |
| 53 | TCP/UDP | DNS | 解析的命脈，常被放大攻擊濫用 |
| 80 / 443 | TCP | HTTP / HTTPS | 網頁服務，443 是加密版 |
| 3306 | TCP | MySQL | 資料庫，**不該對外開放的頭號候選** |
| 5432 | TCP | PostgreSQL | 資料庫，同樣不該對外 |
| 27017 | TCP | MongoDB | 曾發生大量未設定密碼被拖庫的慘案 |
| 3389 | TCP | RDP | Windows 遠端桌面，暴力破解重災區 |
| 8080 | TCP | 常見備用 HTTP 埠 | 注意：任何程式都能「占」這個埠 |

看到非預期的聆聽埠，先 `ss -tlnp` 問「是誰」，再判斷該不該關——這是養成「看到埠就想到服務、看到服務就想到該不該開」的直覺。

## curl：萬用的 HTTP 瑞士刀

`curl` 大概是命令列最通用的網路工具，特別適合跟網頁服務打交道：抓頁面、測 API、帶 Cookie、看回應標頭，全都能做。

```bash
# 抓頁面內容
curl https://example.com

# 只看 HTTP 回應標頭（排查伺服器設定很好用）
curl -I https://example.com

# 送 POST 請求到 API
curl -X POST https://api.example.com/login \\
-d "user=alice&pass=secret"

# 看 TLS 憑證詳細資訊
echo | openssl s_client -connect example.com:443 \\
-servername example.com 2>/dev/null | openssl x509 -noout -dates
```

> curl -k 會跳過憑證驗證，別亂用。 它跳過的是幫你擋中間人攻擊的那道檢查。偵錯時偶爾需要，但「憑證錯誤」本身就是一個必須正視的警告訊號——該查的是為什麼錯，而不是直接繞過。

## dig：DNS 的專用探針

網站掛了，不一定是伺服器掛了——可能是 DNS 找不到路。`dig` 就是專門問 DNS 的工具，它直接跟你系統裡設定的 DNS 伺服器對話：

```bash
# 查詢一個網域名稱的 A 紀錄
dig example.com

# 指定要問哪台 DNS 伺服器
dig @8.8.8.8 example.com

# 只看簡短答案
dig +short example.com

# 反向查詢：IP 對應哪個名稱
dig -x 93.184.216.34
```

`dig +short` 是日常最常用的速查模式。它不只能回答「這名字通不通」，還能交叉比對多台 DNS 伺服器的答案是否一致——不一致時，往往是 DNS 汙染或配置錯亂的警訊。

## nc：測試連線的最後手段

`nc`（netcat）號稱「TCP/IP 的瑞士軍刀」。它的兩個基本用途，正好回答前面三個問題的最後一個：**這台機器能不能跟那台機器講話？**

```bash
# 測試能否連上某個主機的某個埠
nc -zv example.com 443

# 監聽本機的某個埠（測試自己用）
nc -l 12345

# 連上之後，手動送一行文字
echo "hello" | nc example.com 80
```

`nc -zv` 的 `-z` 代表「不送資料，只測試能否連通」，`-v` 顯示詳細結果——這是檢查防火牆與連通性的標準手法。`nc -l` 可以開一個測試埠，方便你驗證「外面到底進不進得來」；用完立刻關掉，別留一個敞開的門在系統上。

## 綜合演練：這台機器到底在跟誰講話？

把這章的工具串成一套偵查流程，你可以在一分鐘內回答「這台機器現在在跟誰講話」：

```bash
# 1. 這台機器有哪些對外網路？
ip addr show

# 2. 哪個程式開了哪些埠？
sudo ss -tlnp

# 3. 目前有哪些活躍的連線、連去哪？
ss -tnp

# 4. 那個連線的 IP 在網路上是什麼名字？
dig -x <那個IP>
```

> 這些指令全都是檢查自己機器的標準維運操作。用同樣的工具去「偵察」別人的伺服器、掃描非授權的目標，在許多司法管轄區是違法的——測試的邊界，永遠以你自己擁有或獲得授權的系統為準。

#### Q: 你要檢查「哪個程式正在監聽 8080 埠」，應該用哪條指令？

* sudo ss -tlnp

* ip addr

* dig example.com

* curl -I example.com

> 💡 ss -tlnp 列出所有正在聆聽的 TCP 埠並顯示對應程式；加上 sudo 才能看到別人的程式。ip addr 看介面 IP，dig 查 DNS，curl 測 HTTP，都不是「查聆聽埠」的工具。
