# Linux 加固基礎

> 📅 2026-08-05 · 使用教學
> 一套務實的伺服器加固起手式：保持更新、精簡服務、防火牆、SSH 金鑰登入與禁用 root、使用者密碼政策、自動更新。不是銅牆鐵壁，而是讓入侵成本高到不值得。

---

## 加固不是買保險，是把門鎖好

「加固」（hardening）聽起來很玄，其實就是把 `linux-07-logs-auditing` 與 `linux-08-networking-cli` 學到的東西反過來用：學會看日誌，才知道要記錄什麼；學會查聆聽埠，才知道哪些門該關。這章給的是**一套務實的起手式**——不需要花錢買設備，只要在系統上照著做八件事，就能把入侵的成本拉高到多數攻擊者寧可去找更軟的目標。

心態很重要：加固的目標不是「不可能被入侵」，而是**「入侵成本 > 目標價值」**。攻擊者像水，永遠流向最低處。你只要不是那條最低的縫，就已經贏了大半。

## 第一件事：把系統保持在最新狀態

聽起來老生常談，但它是所有加固的地基。`linux-06-shell-essentials` 的套件管理不是拿來玩的——**多數入侵，靠的是已修補漏洞的舊版本**。CVE 一公開，攻擊者幾個小時內就能寫出利用程式，而你的防守視窗，就是「從修補釋出到更新完成」這一段。

```bash
# Debian / Ubuntu
sudo apt update && sudo apt upgrade

# Fedora / RHEL 系
sudo dnf upgrade
```

如果你只想記得一句話，那就是：**更新的優先級，永遠排在新增軟體前面**。每次登入伺服器，先問「有沒有待更新的套件」，再想別的事。

## 第二件事：移除與精簡服務

還記得 `ss -tlnp` 嗎？每開一個聆聽埠，就是多一個可能被攻破的入口。加固的黃金規則是：**預設關閉，只開需要的**。凡是伺服器用不到的服務——印表機（cups）、未使用的網頁伺服器、開發用的資料庫——一律停用甚至移除。

```bash
# 看看目前有哪些服務在跑
systemctl list-units --type=service --state=running

# 停用並關閉開機自啟（以 cups 為例）
sudo systemctl disable --now cups
```

> 攻擊面的大小，直接跟「跑著的服務數量」成正比。 移除一個你根本不需要的服務，等於免費刪掉一整類漏洞。這是最划算的一步加固——你甚至不用懂那個服務的任何細節。

精簡的不只是服務，還有使用者帳號。`linux-04-users-groups` 提過的「最小權限」在這裡落地：刪掉閒置帳號、收掉沒人用的 shell、檢查 `/etc/passwd` 裡有沒有來路不明的帳號。

## 第三件事：防火牆，先擋再說

防火牆的哲學跟精簡服務一樣：**預設拒絕，明示允許**。Ubuntu 內建的 `ufw`（Uncomplicated Firewall）是新手友善的起點——它只是把 `iptables`/`nftables` 的複雜語法包裝成簡單指令。

```bash
# 啟用 ufw（小心：啟用前先允許 SSH，否則你會把自己鎖在外面）
sudo ufw allow OpenSSH
sudo ufw default deny incoming
sudo ufw enable

# 允許指定服務或埠
sudo ufw allow 443/tcp
sudo ufw status verbose
```

> 永遠先允許 SSH，再啟用防火牆。 若先啟用再允許，你的下一個動作很可能是看著連線逾時，然後祈禱伺服器有 console 可以救。順序對了，防火牆才是保護，不是陷阱。

伺服器對外的聆聽埠，應該只剩下真正需要公開的：SSH（若需要遠端管理）、443/80（若要對外提供網頁）、以及其他明確需求的服務。其餘全部擋掉。

## 第四件事：SSH 改用金鑰、關掉 root 登入

SSH 是 Linux 伺服器的遠端大門，也是最常被暴力掃描的目標（想想 `linux-07-logs-auditing` 的 auth.log）。大門的加固有兩件非做不可的事：

**第一，改用金鑰登入，禁用密碼登入。** 金鑰是公開金鑰密碼學的應用（`crypto-03-asymmetric-crypto`）：伺服器只認你的公鑰，你的私鑰留在本機。沒有密碼可猜，暴力破解直接失去目標。

```bash
# 在本機產生金鑰對
ssh-keygen -t ed25519

# 把公鑰裝到伺服器上
ssh-copy-id user@your-server

# 編輯 /etc/ssh/sshd_config，然後重啟 sshd
# PasswordAuthentication no
# PermitRootLogin no
sudo systemctl restart ssh
```

**第二，禁用 root 直接登入。** root 帳號只有一個、名字全世界都知道、而且沒有鎖定次數上限——讓 root 能被直接登入，等於在門口掛著「歡迎猜密碼」的招牌。正確做法：用普通帳號登入，需要時再 `sudo`。

## 第五件事：使用者的密碼政策

密碼是伺服器安全鏈裡最脆弱的一環。即使你禁用了 SSH 密碼登入，系統上的本機帳號與服務仍可能用到密碼。`pass-01-how-passwords-are-stored` 講過密碼該怎麼存，這裡講的是**政策**：

* **密碼長度**：強制最小長度，現代建議至少 12 字元以上。
* **到期與歷史**：定期強制更換，但不要逼到使用者把密碼寫在便利貼上。
* **鎖定策略**：連續失敗 N 次後鎖定一段時間，擋下暴力嘗試（這正是 `pass-04-defenses` 的「節流」在系統層的落地）。

Ubuntu 上可以用 `libpam-pwquality` 設定複雜度規則。重點不是「設多複雜」，而是**「不允許弱密碼、不允許無限重試」**。

## 第六件事：開啟自動更新

人會忘記，時鐘不會。**自動更新**是「保持更新」這條紀律的機械化版本——不用你記得，系統自己把安全修補裝好。Ubuntu 的 `unattended-upgrades` 就是幹這個的。

```bash
sudo apt install unattended-upgrades
sudo dpkg-reconfigure --priority=low unattended-upgrades
```

> 自動更新的取捨：它替你省下「記得更新」的心力，代價是「某個更新可能造成不相容」。務實的做法是——安全更新全自動，功能更新你審核。兩害相權，被已公開漏洞打穿，遠比偶爾一次的更新事故常見得多。

## 第七件事：稽核與監控

加固不是「設定好就忘」。`linux-07-logs-auditing` 教的日誌技能，在這裡變成持續的監控：定期檢查 auth.log 有沒有異常、`ss -tlnp` 有沒有多出不認識的聆聽埠、`systemctl` 有沒有冒出未知的服務。把「異常」培養成直覺，你才能在出事第一天發現，而不是事發三個月後。

## 第八件事：建立一套可重複的檢查清單

最後，把前面七件事整理成一份可以照著跑的清單，貼在每次部署新伺服器的流程裡：

* [ ] 套件更新到最新，開啟安全更新自動化
* [ ] 停用或移除不需要的服務與帳號
* [ ] 防火牆預設拒絕，只開必要埠
* [ ] SSH 用金鑰登入，禁用密碼與 root 登入
* [ ] 密碼政策：最小長度、到期、失敗鎖定
* [ ] 定期稽核日誌與聆聽埠
* [ ] 備份設定與資料，並實際演練還原

最後用一張表把八件事濃縮成「一句話」：

| 項目 | 擋住什麼 | 核心動作 |
|------|---------|---------|
| 保持更新 | 已知漏洞的利用 | `apt/dnf upgrade` |
| 精簡服務 | 多餘的攻擊面 | `systemctl disable --now` |
| 防火牆 | 未授權的連入 | `ufw default deny` |
| SSH 金鑰 | 密碼暴力破解 | `ssh-keygen` + 關閉 root 登入 |
| 密碼政策 | 弱密碼與無限重試 | 最小長度 + 失敗鎖定 |
| 自動更新 | 漏補的修補視窗 | `unattended-upgrades` |
| 稽核監控 | 事發後的盲區 | 定期查日誌與聆聽埠 |
| 備份還原 | 系統毀損與勒索 | 備份並演練還原 |

#### Q: 啟用 ufw 防火牆時，為什麼「先允許 SSH」是必要的？

* 否則你可能把自己鎖在伺服器外面，連不回來

* 因為 SSH 是唯一需要開放的服務

* 因為 ufw 無法在沒有 SSH 時啟用

* 因為 SSH 需要搶佔第一個防火牆規則

> 💡 ufw 啟用時若預設拒絕所有連入流量，而 SSH 還沒被允許，你現有的 SSH 連線會被切斷、新連線也會被擋，等於把自己鎖在門外。先允許 SSH 再啟用，是防火牆設定的基本順序。
