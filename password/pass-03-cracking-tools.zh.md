# hashcat 與 John the Ripper 實作

> 📅 2026-08-05 · 工具組
> 認識兩大密碼雜湊分析工具：hashcat 與 John the Ripper。了解 hash 模式、字典、規則與基準測試，學會替自家密碼做健檢。

---

## 兩個名字，同一件事

在 `pass-02-cracking-101` 我們學到，破解的本質是「猜 → 雜湊 → 比對」。而實務上，把這件事做到極致的，是兩個開源工具：**hashcat** 與 **John the Ripper**。它們的用途不是「入侵」，而是**幫你檢視自家密碼有多容易被猜中**——就像用顯微鏡檢查自己的密碼衛生。

兩者的定位稍有不同。hashcat 以 GPU 加速見長，追求極致吞吐量，適合大量雜湊與暴力破解；John the Ripper（簡稱 John）單一機器上很輕巧，雜湊格式自動偵測很強，常被用在「拿到一個不明格式的雜湊，先讓 John 認出來」的場合。多數資安團隊兩者都裝，先 John 後 hashcat。

> 再次強調授權範圍——這些工具只能在你自己的系統、你的測試資料、或明確授權的 CTF/稽核中使用。用它們對任何第三方系統或真實使用者帳號進行測試，是違法行為。本篇文章的所有範例，都假設你在自己的實驗室、處理自己產生的測試雜湊。

## hash 模式：先搞清楚你在對抗什麼

雜湊的世界有很多格式：MD5、SHA-1、bcrypt、argon2、NTLM、以及各種加了鹽的變體。工具裡每一種格式對應一個 **hash mode**。你必須先正確辨識格式，工具才知道該怎麼算——用錯模式，結果一定是錯的。

| 常見 hash mode | 演算法 | 典型用途 |
|---------------|--------|---------|
| 0 | MD5 | 舊系統、校驗（不該再用於密碼） |
| 1000 | NTLM | Windows 帳號 |
| 3200 | bcrypt | 現代網站密碼（刻意慢） |
| 25600 | argon2id | 現代網站密碼（推薦預設） |

怎麼知道手上的雜湊是哪種？看長度、看格式特徵，或直接交給 John 的自動偵測。辨識正確，等於省下一半的時間。

## John 的強項：先認出「這是什麼雜湊」

hashcat 追求吞吐量，而 John the Ripper 的第一個工作通常是**辨識**。當你拿到一串格式不明的雜湊——例如從不知名的舊系統匯出的——John 會自動偵測它的類型，這在節省時間上非常關鍵。

辨識完之後，John 也能用 CPU 做輕量的字典與規則破解。它的預設行為是「先用內建字典與規則跑一輪」，非常適合快速摸底。許多團隊的標準流程是：先讓 John 跑，若發現需要 GPU 等級的吞吐量，再切換到 hashcat。

## 字典：猜測的燃料

工具只是引擎，**字典才是燃料**。字典是一份「候選密碼清單」，從幾百萬詞的超大型字典，到針對特定語言、特定公司命名的客製清單都有。工具會把字典裡的每一行拿來雜湊比對，這是整個流程的起點——因為如前一篇所說，多數真實密碼都在字典的射程內。

選擇字典的邏輯很簡單：先大而通用，再小而精準。一份好的字典不是愈大愈好，而是愈「貼近目標使用者的習慣」愈好。資安團隊會用洩漏的密碼統計，去建構「如果我們的使用者設密碼，會長什麼樣」的模型——這才是健檢的真正價值。

也要注意字典的「新鮮度」：十年前有效的清單，可能已經跟不上今天的命名習慣。定期更新字典，跟定期更新工具本身一樣重要——因為攻擊者用的就是同一批燃料。

## 規則：字典的擴音器

單靠字典還不夠。`pass-02-cracking-101` 提過的**規則變形**，在工具裡就是一排規則檔：`Password`、`Password1`、`P@ssw0rd`……這些都是同一份字典「變出來」的。hashcat 的內建規則集非常豐富，一條規則代表一整套轉換動作。

規則可以無限疊加，但也會讓時間爆炸——每多一條規則，猜測數就多一份字典的量。所以實務上有一個平衡：先用內建且已知效果良好的規則集，觀察命中率，再決定要不要加深。工具會幫你統計命中了多少，這就是評估規則品質的數據。

在 John 那邊，同樣的工作用一句話就能起跑：

```bash
# 讓 John 自動偵測格式並用字典開始嘗試
john --wordlist=rockyou.txt lab-hashes.txt

# 顯示已破解的測試密碼
john --show lab-hashes.txt
```

再次提醒：這些命令面對的，是你自己實驗室裡產生的測試雜湊。John 的輸出行數會直接告訴你——在目前這個字典 + 規則組合下，有多少測試密碼被命中。

## 基準測試：先量自己的「每秒次數」

還記得上一章的等式嗎？`破解時間 = 密鑰空間 ÷ 每秒次數`。**基準測試（benchmark）**就是量出你自己的「每秒次數」，讓你知道面對某種雜湊，你的硬體到底多快。這同時也是評估演算法強度的好方法——如果 bcrypt 在你的高階 GPU 上每秒只能算幾千次，那你對自己系統的防禦等級就有了實感。

```bash
# 1) 在實驗室建立一個測試雜湊（測試用，不是真實帳號）
printf 'Lab-Password-2024' | md5sum

# 2) 用字典攻擊你的測試檔（mode 0 表示 MD5）
hashcat -m 0 lab-hashes.txt rockyou.txt

# 3) 基準測試：看看你的硬體算 bcrypt 有多慢
hashcat -b -m 3200
```

上面的命令都是**對你自己產生的測試雜湊**操作。重點不是記指令，而是看懂每一行在做什麼：建立樣本、指定格式、選擇燃料、量測速度。

## 讀懂工具的輸出

工具的輸出乍看是密密麻麻的統計，其實重點就幾個欄位：

| 輸出欄位 | 意思 |
|---------|------|
| Candidates / Guesses | 目前試了多少個候選 |
| Speed | 每秒猜測次數，就是上一章說的「分母」 |
| Recovered / Cracked | 命中幾個測試雜湊 |
| Time.Estimated | 照目前速度，跑完全部要多久 |

這些數字不是拿來看的，是拿來**做決策**的：速度告訴你演算法強不強，命中率告訴你字典與規則品質，預估時間告訴你該不該換策略。看得懂輸出，健檢才算真的做完。

## 一個完整的健檢流程

用工具替自家密碼健檢，大致是這幾步：

#### 準備測試資料

在自己的實驗室裡，挑一組**自己產生的**測試雜湊，或取自 CTF 題目。絕對不要碰真實使用者的資料。

#### 識別雜湊類型

確認 hash mode：是 MD5、NTLM、bcrypt 還是 argon2？加鹽了嗎？先認清楚再動手。

#### 由快到慢地猜

先字典，再規則，最後才是暴力破解。一開場就暴力不是專業，是浪費電。

#### 解讀結果

命中率高，代表樣本密碼偏弱，該建議更換演算法或宣導密碼管理器。把建議寫成報告交給防禦方。\n\n→ next: pass-04-defenses

健檢的產出不是「我破解了什麼」，而是一份**風險報告**：樣本裡有多少密碼落在字典射程內、演算法是不是太舊、要不要升級到 argon2id。攻擊面是你的資料、回報是給防禦方的建議——這就是藍隊思維。

## 把健檢變成例行公事

一次性的健檢只能反映當下的狀態。更務實的做法，是把密碼健檢變成**例行流程**：

* 當使用者設定或重設密碼時，即時比對洩漏清單與弱字典，擋下已被公開的密碼；
* 定期重跑基準測試，確認硬體升級沒有偷偷把保護等級降下去；
* 每隔一段時間重跑字典與規則，檢視「我們的樣本密碼有沒有愈來愈弱」。

有些工具甚至提供 API，讓註冊/登入流程在設定密碼的那一刻就攔截弱密碼。這把 `pass-04-defenses` 要講的洩漏監控，直接變成了一道即時防線，而不是每年一次的事後檢討。

## 常見陷阱

用這些工具時，有幾個新手常踩的坑：

* **用錯 hash mode**：格式辨識錯誤，結果全錯，還以為「這個密碼破解不了」。
* **拿真實資料測試**：即使只是內部測試，真實使用者雜湊也牽涉隱私與合規，實驗室一律用自造樣本。
* **無視基準測試**：不先量速度，就無法估算要跑多久，計畫很容易失控。
* **字典優先級錯誤**：跳過字典直接暴力，等於放棄最高效率的攻擊面。
* **只看命不命中**：命中率低不一定是壞消息，可能是樣本本來就夠強；重點是比較「同一批樣本在不同演算法/規則下的表現」。

記住一句話：工具本身不危險，**拿來做什麼**才有對錯之分。同樣的指令，用在自家實驗室是健檢，用在別人的系統就是犯罪。

工具只是把 `pass-02-cracking-101` 的機制實作化。它們存在的意義，是讓你知道**你面對的雜湊有多快被打穿**，進而逼你認真面對防守。下一篇就是整個系列的重頭戲：`pass-04-defenses` 會告訴你，怎麼用慢雜湊、密碼管理器、通行金鑰與 MFA，把前面兩章練出來的「每秒次數」全部打回原形。

#### Q: hashcat 的「hash mode」指的是什麼？

* 要使用的雜湊演算法格式，例如 MD5、bcrypt 或 argon2

* 你的 GPU 時脈頻率

* 字典檔案的大小上限

* 攻擊時的網路連線模式

> 💡 hash mode 告訴工具該用哪種演算法來計算與比對雜湊。格式辨識錯誤，結果就會完全錯誤。
