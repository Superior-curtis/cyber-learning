# 防禦：MFA、密碼管理器與鎖定策略

> 📅 2026-08-05 · 核心概念
> 把前兩章的所有弱點補起來：慢雜湊、密碼管理器、通行金鑰、MFA、鎖定與洩漏監控。為什麼「長隨機 + 管理器 + MFA」才是最佳組合。

---

## 防守方也有自己的武器庫

前兩章把攻擊者的牌都攤開了：字典、暴力、規則、GPU、彩虹表。讀到這裡你可能覺得防不勝防——但別忘了，防守方也有自己的武器庫，而且每一件武器都精準對應一個弱點。這一章，就是把 `pass-02-cracking-101` 和 `pass-03-cracking-tools` 揭露的每一個縫隙，系統性地補上。

先記住這條主線：**破解時間 = 密鑰空間 ÷ 每秒次數**。防禦的一切，都是讓分子變大、或讓分母變小。下面的每一道防線，都可以套進這條等式。

## 第一道：把雜湊換成「刻意慢」的演算法

還記得 GPU 面對 MD5 每秒能試幾十億次嗎？那是最糟的起點。防守方的第一件事，是確認系統**根本不用快速雜湊存密碼**。選擇現代密碼雜湊（argon2id、bcrypt、scrypt），並為每個帳號加獨立的鹽——這點在 `crypto-02-password-hashing` 有詳細原理。

> 演算法是速度門檻，不是細節。 同樣一顆 GPU，argon2id 能把每秒嘗試次數壓到 MD5 的百萬分之一。升級演算法，等於讓你的每一個密碼都「憑空變長」好幾個字元。

為什麼用 `pass-03-cracking-tools` 的基準測試就能驗證？因為你可以自己跑一次 `hashcat -b -m 25600`，親眼看到速度慢到什麼程度。數字會說話——這就是為什麼演算法選擇永遠排在防禦清單最前面。

## 第二道：密碼管理器，讓「長隨機」真正可行

前面反覆強調「長隨機密碼」——但人類不可能記住一百個完全不一樣的 20 字元密碼。於是出現了最被低估的防禦工具：**密碼管理器**。它替你產生、儲存、填入高強度隨機密碼，你只需要記住一個主密碼。

密碼管理器解決的不只是「長度」，還有**重複使用**。密碼重用是字典攻擊的養分：一份洩漏的舊密碼，可以拿去試你所有的帳號。管理器讓每個網站都用獨一無二的密碼，即使某個站被拖庫，其他帳號也毫髮無傷。

選管理器的重點：選擇加密本地儲存、開放原始碼或經第三方稽核的產品，並開啟雙重驗證保護主密碼。它值得一個你在意的選擇。

## 插曲：長度下限與通行短語

與其強迫使用者在 8 位密碼裡塞進各種符號，不如直接把**長度下限**拉高。**通行短語（passphrase）**——幾個隨機單字串在一起，例如 `celery orbit velvet tractor`——靠長度撐起密鑰空間，而且對人類來說意外地好記。

這正好對上 `pass-02-cracking-101` 的結論：長度比複雜度重要。一個 20 字元的通行短語，即使只用小寫字母，密鑰空間也比 10 字元的「大小寫+數字+符號」大上許多。密碼管理器的自動產生器，通常也傾向於長隨機字串而非複雜短字串——因為後者只是「看起來」安全。

## 第三道：通行金鑰，密碼的接班人

**通行金鑰（passkeys）**想讓密碼本身退役。原理是公鑰密碼學（`crypto-03-asymmetric-crypto`）：伺服器只存你的公鑰，私鑰留在你的裝置裡，登入時用生物辨識解鎖、以簽章證明身分。

對抗這本書裡的每一種破解手法，通行金鑰都有先天優勢：沒有密碼，就沒有雜湊可猜；私鑰不出裝置，釣魚網站根本騙不到。這是最接近「從根源解決」的方案——但推廣需要生態系配合，所以對多數系統來說，它的地位是「現代密碼的加強版」，而不是立刻替換掉一切。

## 第四道：MFA，讓「猜中密碼」變得不夠

密碼再強，總有洩漏的一天。**多因子驗證（MFA）**的邏輯是：即使攻擊者拿到了你的密碼，還需要第二個因子才能登入。第二因子屬於不同類別——不是你「知道」的，而是你「擁有」的（手機、安全金鑰）或「是」的（指紋、臉部）。

但 MFA 也有等級之分：

| MFA 類型 | 例子 | 對抗釣魚 |
|---------|------|---------|
| SMS 簡訊 | 一次性驗證碼 | 弱（可被 SIM 換卡攻擊） |
| TOTP 驗證器 | Google Authenticator、Authy | 中 |
| 推送確認 | 手機通知按「允許」 | 中 |
| 通行金鑰 / FIDO2 安全金鑰 | YubiKey、平台通行金鑰 | 強 |

**防釣魚的 MFA**（FIDO2、通行金鑰）把憑證綁定到特定網站網域，釣魚頁面拿到也無法重放。如果你的系統要選 MFA，優先選防釣魚變體——這是 `blue-06-phishing-defense` 的詳細戰場。

## 插曲：別讓安全問題成為後門

「你的第一隻寵物叫什麼？」「你的家鄉在哪？」這類**安全問題**常出現在帳號復原流程裡——但它們往往是字典與 OSINT（`recon-01-recon-osint`）的完美靶子：答案可以在社群媒體上找到，或根本是常見名字。最理想的做法是乾脆不設安全問題，改用備用驗證碼、MFA 復原或通行金鑰；若必須保留，也要把它當成另一個秘密來對待，並套用同樣的節流保護。

## 第五道：鎖定與節流，讓暴力破解失去意義

還記得上一章的等式嗎？分母是「每秒次數」——攻擊者用 GPU 把分母縮小。但如果你在**伺服器端**限制嘗試次數，情況就反過來：無論 GPU 多快，每一秒你只允許它試一次。

* **帳號鎖定**：連續失敗 N 次後鎖定一段時間。
* **節流（throttling）**：限制同一 IP 或同一帳號的登入速率。
* **驗證碼與延遲**：增加人與機器的辨識成本。

副作用要小心：攻擊者可以利用鎖定策略對你的使用者發動**鎖定攻擊**（把別人的帳號鎖到不能登入）。所以實務上，節流通常比硬鎖定更受歡迎——它拖慢攻擊者，但不傷及無辜。

## 第六道：洩漏監控，知道密碼已經外流

最好的密碼，是你知道它已經外流的那個——然後立刻換掉。**洩漏監控**服務（如 Have I Been Pwned）匯集已公開的洩漏資料庫，讓你可以查詢自己的信箱或密碼是否出現在已知洩漏中。

企業可以做的更進一步：把內部密碼的雜湊拿去比對洩漏清單，找出**員工或使用者正在使用已被公開的密碼**，然後強制重設。這正是 `pass-03-cracking-tools` 的健檢流程在生產環境的延伸——攻擊者用同一份資料，防禦者也要用。

## 插曲：教育宣導要講「為什麼」

過去的密碼規定常常是「12 位以上、含大小寫與符號、每 90 天換一次」——只告訴使用者做什麼，沒告訴他們為什麼。現代密碼政策的宣導重點已經轉移：教使用者用**密碼管理器**、認識**通行金鑰**、以及理解**為什麼不要重用密碼**。當使用者理解「重用 = 一份洩漏打全部」時，他們往往比被迫定期換密碼更願意守規矩。

## 第七道：把三件事組合起來

個別防禦都有效，但真正的安全來自組合。為什麼「長隨機 + 管理器 + MFA」能勝過複雜度規則？

| 策略 | 對抗什麼 | 弱點 |
|------|---------|------|
| 複雜度規則（強制大寫+數字+符號） | 純暴力破解 | 難記 → 重用 → 反而變弱 |
| 長隨機密碼 | 字典、規則、暴力 | 人記不住 → 需要管理器 |
| 密碼管理器 | 重用與弱密碼 | 主密碼被釣魚 |
| MFA（防釣魚） | 密碼洩漏、釣魚 | 需生態系配合 |
| 慢雜湊 + 鹽 | GPU 吞吐 | 只保護伺服器端 |

複雜度規則看似嚴格，卻逼人把 `Password1!` 寫在便利貼上、或每個網站重複使用——等於把攻擊面從「暴力破解」轉移到「洩漏重用」這個更常發生的地方。而「長隨機 + 管理器 + MFA」每一件都消滅一整類攻擊，且互相補上彼此的洞。**這是比「記住更複雜的密碼」更務實的現代答案。**

## 一頁防禦檢查清單

把整章濃縮成一張可以照著核對的清單，適合貼在團隊牆上：

* [ ] 密碼用 argon2id、bcrypt 或 scrypt，且每個帳號獨立加鹽
* [ ] 密碼儲存絕不使用快速雜湊（MD5、SHA-1）
* [ ] 推行密碼管理器，禁止密碼重用
* [ ] 長度下限 ≥ 12，或採用通行短語
* [ ] 所有登入都啟用 MFA，優先防釣魚變體
* [ ] 登入與復原流程都有節流與速率限制
* [ ] 定期比對洩漏清單，發現外流立即重設
* [ ] 教育宣導講「為什麼」，而不是只列規則

每一項都能對回本章的一整節。若你發現哪一項做不到，就從那一節開始補——防禦不是一次到位，而是逐項推進。

## 別忘了復原流程

再好的鎖，使用者總有一天會忘掉鑰匙。帳號復原是攻擊者最喜歡的捷徑之一——「忘了密碼」流程設計得不好，等於把前面七道防線全部繞過。復原流程的幾個原則：只能發送到你驗證過的管道（不是可變更的號碼或信箱）、帶上 MFA、對復原嘗試同樣節流、並在復原後通知使用者。防禦是整條鏈，不是某一環。

## 當最壞情況發生：偵測與回應

防禦再完整，也不能假設「永遠不會被繞過」。所以還要有偵測與回應的一環：

* **異常登入告警**：新裝置、新地點、凌晨三點的登入，都是值得提醒使用者的訊號。
* **登入失敗趨勢**：單一帳號大量失敗，或大量帳號各自失敗一兩次（密碼噴灑的典型特徵），都應該觸發告警。
* **憑證變更通知**：密碼被改、MFA 被重設、復原流程被執行——這些事件要在第一時間通知本人。

偵測的細節會由 `blue-02-logging-siem` 與 `blue-04-incident-response` 深入展開。這裡要記住的主線是：密碼防禦不是「設好就忘」，而是一個「防護 → 偵測 → 回應」的循環。

## 企業層級：SSO 與零信任

個人可以靠管理器與 MFA，企業還需要**身分基礎設施**。**單一登入（SSO）**讓員工只用一組企業憑證進出所有內部系統，密碼管理集中、稽核也集中；**條件式存取**可以針對裝置、地點與風險狀態決定放行與否。這些概念會在 `blue-07-iam-zero-trust` 完整展開——這裡只要記住主線：把「一個系統一套密碼」收斂成「一個身分中心 + 多因子」，攻擊面就會大幅縮小，`pass-05-real-breaches` 裡那種「一份密碼打全部」的悲劇也就少了最大的一塊溫床。

## 一步的總結

從攻擊機制的角度重看整章：字典怕長隨機，規則怕不按套路，GPU 怕慢雜湊，彩虹表怕鹽，洩漏重用怕管理器，釣魚怕防釣魚 MFA，暴力破解怕節流。防禦不是一道銅牆鐵壁，而是一組互相咬合的齒輪——每一個都讓「每秒次數」更小、或讓「密鑰空間」更大。
