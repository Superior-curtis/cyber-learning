# 掃描與列舉：nmap 入門

> 📅 2026-08-05 · 使用教學

---

`net-01-network-fundamentals` 告訴你，埠就是「門」，而「哪個埠開著」是資安最經典的第一個問題。回答這個問題的標準工具叫 **nmap**——一個幾乎所有資安人都會用的網路掃描器。

這篇教你從零開始：nmap 怎麼用、怎麼讀輸出，以及最重要的——**只掃描你有權限的機器**。最後我們還從防守方角度看一眼，掃描在你的日誌裡長什麼樣。

> 授權與界線：nmap 是向目標主動發送網路請求的工具，每一次掃描都會在目標留下痕跡。只掃描你自己的機器、CTF 練習靶機、或你有書面授權的範圍。未經授權掃描，在多數地方都是違法行為。

## 掃描在幹嘛

想像你在一個社區外面，想知道每棟房子的門開著幾扇、門上寫著什麼。掃描就是在做這件事：**向目標的某個 IP 發送連線請求，觀察哪些埠有回應，並嘗試辨識背後跑的服務。**

對防守方而言，這份資訊同樣珍貴：**你的機器在別人眼中開了哪些門？** 先知道，才能先處理。

## 第一個掃描

nmap 的基礎用法非常簡單——給它一個目標：

```bash
# 掃描你自己的本機，看常見埠
nmap 127.0.0.1

# 加 -sV 嘗試辨識服務版本（更慢但更有用）
nmap -sV 127.0.0.1

# 指定要掃的埠
nmap -p 22,80,443 192.168.1.10
```

第一次跑通常只要幾秒。輸出大致長這樣：

```
PORT     STATE SERVICE
22/tcp   open  ssh
80/tcp   open  http
```

`STATE` 欄位是重點：`open` 代表「這扇門開著」——也就是說，這個服務正在接受連線。這正是攻擊面（attack surface）的一部分。

## 常用旗標

| 旗標 | 作用 |
|---|---|
| `-sV` | 辨識服務版本 |
| `-p 80,443` | 指定埠；`-p-` 掃全部埠 |
| `-O` | 嘗試辨識作業系統（需要權限，較慢） |
| `-oA output` | 把結果存成檔案 |
| `-T4` | 加快掃描速度（謹慎使用，愈快愈容易被偵測） |

> 少即是多。 新手最常犯的錯是「全埠 + 最快速度」一次梭哈。對自己有權限的機器，先掃常用埠、看清楚服務，比盲掃幾萬個埠更有價值。

## 防守方眼中長什麼樣

這是最容易被忽略的一課：**掃描不是無形的。**

你發出的每個連線請求，都會出現在目標的日誌裡——防火牆記錄、服務日誌、`/var/log` 裡全都有痕跡。`linux-07-logs-auditing` 講過的那些日誌，正是在記錄「誰來敲過門」。防守方如果做好 `blue-02-logging-siem`，看到一小段時間內大量失敗連線到不同埠，通常就會觸發警示。

這代表兩件事：

1. 對攻擊者來說，掃描本身可能就是警報——這就是為什麼很多工具會故意放慢或混淆。
2. 對防守方來說，**你應該知道自己的日誌長什麼樣**，這樣當掃描發生時，你才認得出來。

## 列舉：掃描之後

掃描告訴你「門開著」，但「門後是什麼」要靠**列舉（enumeration）**——更深入地詢問服務本身：跑了什麼版本、有沒有歡迎橫幅、存不存在已知漏洞。這個「掃描 → 列舉 → 判斷漏洞」的流程，是 `kali-07-enumeration-tools` 與 `cve-03-reading-a-cve` 要接下去講的故事。

## 下一步

你已經會掃描自己的機器了。下一步往防守端走：`blue-02-logging-siem` 教你怎麼把日誌變成「看得到誰在敲門」的眼睛——知道自己的門、也知道敲門聲，資安的兩隻腳就都站穩了。

#### Q: 為什麼未經授權使用 nmap 掃描他人系統是嚴重問題？

* 因為 nmap 會直接破壞目標系統

* 因為掃描會主動接觸目標、留下痕跡，且未授權即違法

* 因為 nmap 只能掃描 Windows

* 因為掃描結果永遠不準

> 💡 nmap 向目標主動發送請求，每一次掃描都會在日誌留下痕跡；未經授權掃描在法律與倫理上都不被允許。
