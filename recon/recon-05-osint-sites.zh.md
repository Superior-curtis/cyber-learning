# OSINT 網站與工具地圖

> 📅 2026-08-05 · 使用教學
> OSINT 的來源散落各處——whois、DNS、歷史網頁、程式碼、搜尋引擎、社交平台。這篇把常用的公開來源整理成一張地圖，並教你怎麼有紀律地蒐集。全部只限公開資訊與授權範圍。

---

`recon-01` 到 `recon-04` 講了 OSINT 的思維、搜尋、工具與 Shodan。這篇把整個工具箱攤開：**一張「OSINT 網站與工具」地圖**——哪些來源、能問什麼、怎麼有紀律地蒐集。

> 界線提醒：以下全是公開來源。你「查到」不等於「能使用」——訪問任何需要權限的內容、或對真實個人做騷擾式調查，都是越界。recon-01-recon-osint 的倫理段落，這裡原封不動適用。

## 來源分類

| 類別 | 在做什麼 | 代表來源 |
|---|---|---|
| 註冊與 DNS | 網域背後的資訊 | whois、dig、SecurityTrails |
| 搜尋 | 公開索引的頁面與檔案 | Google dorks、Bing |
| 歷史 | 舊版頁面與已刪除內容 | Wayback Machine |
| 程式碼 | 公開的程式與設定 | GitHub、GitLab |
| 裝置 | 連上網的服務 | Shodan、Censys |
| 社交 | 公開的個人與組織資訊 | 各平台公開頁面 |
| 影像 | 圖片與其來源 | 反向圖片搜尋 |

## 幾把「必備」的公開來源

把清單縮到幾把最常用的：

| 工具/網站 | 能問什麼 |
|---|---|
| whois / RDAP | 網域註冊資訊、DNS |
| Wayback Machine | 網站過去長什麼樣、被刪的頁面 |
| Shodan / Censys | 公網裝置與服務（`recon-04-shodan-deep-dive`） |
| GitHub 搜尋 | 公開程式碼裡洩漏的設定與金鑰 |
| Google dorks | `site:`、`filetype:`（`recon-02-dorking`） |
| 反向圖片搜尋 | 一張圖片的來源與地點 |

> 把「來源」想成「問問題的管道」。 每個來源都擅長回答某一類問題——先想清楚「我要問什麼」，再挑對應的來源，比漫無目的地逛一堆網站有效率得多。

## 有紀律的蒐集流程

OSINT 蒐集不是「到處逛」，而是一套有順序的流程：

#### 定義問題

你想知道什麼？目標網域、一個人、還是一張照片？

#### 先被動

whois、DNS、搜尋引擎、歷史存檔——完全不動到目標。

#### 再主動

在授權範圍內，訪問公開頁面、做更深入的查詢。

#### 記錄與交叉

把線索記下來，從不同來源交叉比對，找出關聯。

## 倫理：蒐集的界線

不管工具多方便，界線不變：

* ✅ 可以：公開的 whois、DNS、搜尋結果、歷史頁面、公開程式碼。
* ❌ 不可以：繞過權限、訪問私密內容、對真實個人做騷擾式調查、把「查到」變成「使用」。
* ⚠️ 記住：**資訊公開 ≠ 授權使用。** `kali-12-osint-tools` 與 `recon-01-recon-osint` 的界線，是你帶走最重要的一課。

* 直接訪問目標系統

* 先定義問題，再用對應的公開來源（whois、搜尋、歷史）開始被動蒐集

* 下載所有可用的工具

* 對真實個人展開調查

> 💡 先問清楚『要知道什麼』，再用對應來源做被動蒐集——有紀律的流程，比亂逛高效也安全得多。
