# 威脅、漏洞與緩解

> 📅 2026-08-05 · 核心概念
> Domain 2 的 22% 都跟「壞事」有關：惡意軟體、社交工程、威脅行為者與漏洞分類。這篇用防禦者視角，把每一種威脅都配上它的解藥。

---

Domain 1 給你詞彙，Domain 2 給你**壞人百科**。它是 SY0-701 比重第二高的領域（22%），也是考生最容易「背了一堆名字卻不知道怎麼用」的地方。

關鍵心態：**這一篇的主角不是威脅，而是「威脅 → 防禦」的配對。**考試幾乎都是「某種攻擊發生，選正確的防禦」。所以這篇文章的每一節，我都會把緩解放在跟威脅一樣重要的位置。

這一篇的結構照著 Domain 2 的大綱走：先認識惡意軟體與社交工程（「人與程式怎麼發動攻擊」），再認識威脅行為者與漏洞分類（「誰在攻擊、從哪裡下手」），最後收束成一套緩解的思考流程。

> 教育與防禦導向——本篇文章用防禦者視角介紹威脅，目的是讓你理解攻擊怎麼發生、以及怎麼擋住它們。這些知識只該用於自己的系統、實驗室環境與明確授權的測試。對不屬於你的系統發動攻擊，是違法的。

## 惡意軟體家族：每一種都配一個解藥

惡意軟體（malware）不是單一威脅，而是一整個家族。SY0-701 會考你認出每一種的「行為特徵」，以及最有效的防禦：

| 惡意軟體 | 它做什麼 | 主要防禦 |
|---|---|---|
| 病毒（virus） | 附在檔案或程式上，執行時感染其他檔案 | 防毒軟體、不開來路不明的附檔、定期更新 |
| 蠕蟲（worm） | 自我複製並自行散播到其他機器，不需要使用者操作 | 修補漏洞、網路分段、防火牆規則 |
| 木馬（trojan） | 偽裝成正常軟體，偷偷執行惡意行為 | 只裝來源可信的軟體、檢查簽章與雜湊 |
| 勒索軟體（ransomware） | 加密你的檔案，要求贖金才還你 | **離線備份**、最小權限、電子郵件過濾 |
| 間諜軟體（spyware） | 在背景偷錄你的活動、按鍵與資料 | 防毒、限制安裝來源、瀏覽器權限 |
| 根套件（rootkit） | 藏進系統底層，企圖躲避偵測 | 安全開機、完整性檢查、乾淨重灌 |
| 殭屍網路（botnet） | 把大量被控的機器組成網路，聽從指令 | 修補、網路監控、封鎖命令與控制伺服器 |

幾個解題重點。第一，**病毒與蠕蟲的分別在「需不需要使用者動手」**：病毒通常要你執行檔案才感染，蠕蟲自己會爬。第二，**勒索軟體最有效的防禦是備份**——而且最好是離線備份，因為被加密的當下，線上的備份可能也被加密了。第三，看到「躲偵測」的關鍵字，先想到根套件。

還要注意：惡意軟體不會自己飛進系統，它需要一個**傳遞管道**——釣魚信附檔、惡意網站的下載、被感染的 USB、漏洞攻擊套件。你發現了嗎？這些管道幾乎都繞著「人會做的事」轉：點開信、插上 USB、逛到壞網站。所以惡意軟體防禦的第一道防線，常常不是技術，而是**不讓使用者把門打開**。

## 社交工程：攻擊的是人，不是系統

社交工程（social engineering）是本書最強調「防禦」的主題之一，因為它繞過所有技術防禦，直接攻擊最軟的一環——人。SY0-701 會考每一種手法的特徵與對策：

| 手法 | 怎麼騙 | 怎麼防 |
|---|---|---|
| 釣魚（phishing） | 大量寄出偽裝信件，騙你點連結或給資料 | 電子郵件過濾、檢查網址、訓練、通報 |
| 魚叉釣魚（spear phishing） | 針對特定人或單位客製內容 | 對高風險角色（財務、管理）加強警戒 |
| 鯨釣（whaling） | 鎖定高階主管等高價值目標 | 大額轉帳雙人覆核、額外驗證程序 |
| 語音釣魚（vishing） | 用電話裝熟、假冒客服或長官 | 回撥官方號碼確認、不洩漏敏感資訊 |
| 簡訊釣魚（smishing） | 用簡訊發送釣魚連結 | 不點不明連結、啟用驗證器 App |
| 偽託（pretexting） | 先編一個可信身分（「我是 IT 支援」）再索取資訊 | 驗證來電者身分、走正式流程 |
| 誘餌（baiting） | 用好奇心釣你（免費 USB、掃碼送禮） | 不明的 USB 不插、來路不明的 QR 不掃 |
| 尾隨（tailgating） | 跟著刷卡的人一起進門 | 實體門禁、一人一卡、反尾隨通道 |

社交工程的共同對策，是**「驗證身份，再信任」**：接到自稱長官的電話，回撥官方分機；收到「更新密碼」的信，自己打開官網輸入網址，不要點信裡的連結。這背後的觀念，其實就是 Domain 1 的零信任——只是這裡驗證的是人。

為什麼這些手法如此有效？因為它們攻擊的不是邏輯漏洞，而是**人性的預設**：我們傾向相信權威（「長官」）、相信緊急（「立刻處理」）、相信友善（「客服」）。攻擊者只要做出一個「看起來合理」的情境，多數人不會停下來驗證。這也解釋了為什麼「先驗證再信任」是唯一通用的對策——它不考驗你的判斷力，而是把驗證變成固定動作。

## 威脅行為者：誰在攻擊你

同一種攻擊，背後的**動機與資源**完全不同，防禦策略也不同。SY0-701 常考的分類：

| 行為者 | 動機 | 資源 | 你需要防什麼 |
|---|---|---|---|
| 國家級（nation-state） | 政治、間諜、地緣 | 極高 | 最有耐心的對手，重視持久與隱密 |
| 犯罪集團（cybercriminal syndicate） | 錢 | 高 | 勒索、詐騙、竊取資料轉賣 |
| 行動主義者（hacktivist） | 理念、抗議 | 中低 | 網站塗改、DDoS、公開資料 |
| 內部人（insider） | 不滿、金錢、或只是粗心 | 中 | 權限管控、行為監控、離職回收權限 |
| 腳本小子（script kiddie） | 好玩、想出名 | 低 | 拿現成工具亂試，修補基本漏洞就有用 |

一個務實的觀念：**威脅建模要先問「誰會盯上我」**。一個小公司不太需要為國家級對手的資源做準備，但它一定要防犯罪集團的勒索軟體。威脅行為者決定你資源該往哪放——`found-04-threat-modeling` 會教你把這個思考變成系統化流程。

還有一點值得強調：**這些分類不是鐵律**。同樣一群人可能既是犯罪集團、也受國家支援；內部人可能是故意的，也可能只是粗心。考試給你的是「最可能」的答案，不是絕對的答案——所以判斷時看「動機＋資源」這兩個軸，而不是硬背分類表。

## 漏洞的大類：弱點從哪裡來

漏洞（vulnerability）是「可以被威脅利用的弱點」。Domain 2 會考的不是單一 CVE（那個在 `cve-01-what-is-cve` 講），而是**漏洞的大分類**：

| 漏洞類別 | 例子 | 緩解 |
|---|---|---|
| 設定錯誤（misconfiguration） | 預設密碼沒改、雲端儲存桶設成公開 | 設定基準、定期稽核、自動化檢查 |
| 未修補的軟體（unpatched） | 已知漏洞但沒更新 | 修補管理、自動更新、資產清單 |
| 弱憑證（weak credentials） | 簡單密碼、沒有 MFA | 密碼政策、MFA、阻止常見密碼 |
| 不安全的設計（insecure design） | 登入沒有速率限制 | 安全設計原則、威脅建模、測試 |
| 個人資料暴露（PII exposure） | 不必要地蒐集與留存敏感資料 | 資料最小化、加密、權限控管 |
| 零日漏洞（zero-day） | 廠商都還不知道的漏洞 | 深度防禦、監控異常、快速應變計畫 |

注意這些類別的緩解，幾乎都是**程序面**的：修補管理、設定基準、最小權限。漏洞不是你「掃一次就結束」的事——它是持續的紀律。`blue-01-hardening` 會把加固與修補講得更完整。

補一個實務觀念：**漏洞掃描（vulnerability scanning）**是找出這些弱點的主要工具——它掃描系統、比對已知漏洞資料庫、產生一份「哪裡有洞」的清單。但掃描只是開始：清單要排優先順序（哪個漏洞最容易被利用？受影響的系統多重要？）、排出修補時程、然後驗證修補真的生效。未修補的漏洞是企業被入侵的第一大原因——不是因為攻擊多難，而是因為修補沒被當成持續的紀律。

## 先分清三個詞：威脅、漏洞、風險

考題很愛用這三個詞，先釐清它們的關係：**威脅（threat）**是可能造成傷害的事物（勒索軟體、釣魚者）；**漏洞（vulnerability）**是你可以被利用的弱點（沒修的程式、弱密碼）；**風險（risk）**是「威脅碰上有漏洞」之後，實際造成損失的可能性與後果。

用一句話串起來：**威脅沿著漏洞滲透，就產生風險。**有威脅但沒有漏洞，風險很低；有漏洞但沒有威脅盯上，風險也不高——但對多數系統來說，威脅一直都存在，所以控制漏洞，就是在控制風險。這個三連關係，也是 `found-04-threat-modeling` 的核心；之後談治理時，`secplus-06-governance-risk` 還會再回來用一次。

## 供應鏈與第三方風險

Domain 2 還有一個常被低估的類別：**供應鏈風險**。你用的軟體來自第三方，第三方用的套件又來自第四方——每一層都是潛在的弱點。近年最有名的供應鏈事件，是把惡意程式偷偷放進熱門開源套件，讓所有使用該套件的公司一次中招。

防禦做法：只依賴可信任的來源、驗證套件的完整性（簽章與雜湊）、保留軟體物料清單（SBOM）以便快速追蹤，以及把「信任第三方」當成一種需要管理的風險，而不是預設。對考試來說，記住「供應鏈風險 = 你的安全依賴著一群你不認識的人」這個直覺，就足以回答絕大多數題目。

## 緩解的核心心法：先知道，再封鎖

把這一整篇壓縮成一個流程，大概是這樣。盤點 → 評估 → 布防 → 驗證，這個迴圈沒有終點——新的威脅出現、系統改變、人員流動，每一步都要重來：

#### 盤點你的資產

不知道自己有什麼，就不知道要保護什麼。先有資產清單。

#### 評估風險

誰會盯上你（威脅行為者），你的弱點在哪裡（漏洞分類），配上後果輕重。

#### 分層布防

用 Domain 1 的控制類型——預防、偵測、矯正——每一種威脅都至少配一層。

#### 驗證與演練

修補要驗證真的生效，計畫要演練才確定能跑。備份還原尤其要真的還原一次。

> 威脅配對練習是準備 Domain 2 最有效的方法：看到一個名詞（例如「勒索軟體」），不要停下來，強迫自己馬上說出它的防禦（「離線備份」）。練習到「威脅 → 防禦」變成反射，考題就贏了一半。

最後一個提醒：緩解不是「全部都要做到」，而是**先做高影響、低成本的事**。改掉預設密碼、開啟自動更新、做好離線備份——這三件事的防禦價值，往往勝過一堆昂貴的防禦工具。把基礎打穩，再往上疊。

## Domain 2 的應考策略

把這一整篇的準備方式收束成三句話：

* **背分類，但更要背配對**——看到每個威脅，都要能瞬間說出它的防禦；
* **注意「行為特徵」**——考題常描述行為（「自我複製並散播」）而不是直接給名字，認出行為就認出了威脅；
* **防禦優先**——看到任何威脅，先想防禦，再想細節。

這三句話，配上 `secplus-07-practice-questions` 的綜合練習，Domain 2 就能穩穩拿下。
