# 安全架構與設計

> 📅 2026-08-05 · 核心概念
> 好的安全是「設計」出來的，不是事後補上去的。網路分段、安全協定、安全基準線，以及雲端與 IoT 的安全基礎——這是系統在藍圖階段就決定的那一半安全。

---

## 好房子從設計圖開始

很多人以為安全是「買」來的：買一台防火牆、裝一套防毒軟體，系統就安全了。但真實世界的安全比較像蓋房子——承重牆、逃生梯、水電管線的位置，早在設計圖階段就決定好了。等房子蓋完才想改，代價是整面牆重新鑿開。**安全架構（security architecture）**就是這張設計圖：系統在藍圖階段就決定的那層防護。

在 `secplus-03-threats-mitigations` 認識了各種威脅與緩解手法之後，這一章往上游走一步：不是「哪裡被打」，而是「怎麼設計才不容易被打」。這一章看的不是某一台設備，而是整體形狀——網路怎麼切、協定怎麼選、機器從什麼基準線出發、雲端與 IoT 誰負責什麼。先記住一句話：**設計得不好的系統，再多的產品也救不回來；設計得好的系統，很多攻擊根本不會發生。**

## 安全設計五原則

無論是哪一種系統，架構設計幾乎都圍繞五條原則打轉。它們是判斷「這個設計合不合理」的快速尺規：

| 原則 | 一句話 | 實際例子 |
|------|--------|---------|
| 最小權限（least privilege） | 只給完成工作所需的最小權限 | 備份帳號不能刪除資料 |
| 縱深防禦（defense in depth） | 不只一道防線，每一層都有獨立防護 | 防火牆之外還有認證、加密、監控 |
| 失效安全（fail secure） | 出錯時關上門，而不是打開門 | 斷電的門禁應該是鎖上的 |
| 零信任（zero trust） | 不信任任何網路位置，每次都驗證 | 內部網路的請求也要驗證身分 |
| 預設安全（secure by default） | 新裝好的系統本來就是安全的 | 關閉不必要的服務與預設密碼 |

> 「最小權限」是五條裡最常被忽略的一條。 大部分入侵不是靠高超技巧，而是靠一個權限過大的帳號。設計階段就把權限拆小，攻擊者就算拿到一個帳號，也只能橫向移動一小步。

這五條原則會一路貫穿到 `secplus-05-security-operations` 的日常營運——那裡的每一項工作，本質上都是把這五條原則「維持」住。

## 存取控制模型：誰可以碰什麼

架構設計的另一個核心問題是：**誰可以碰什麼？** 這就引出**存取控制模型（access control model）**——一套決定「使用者能對哪些資源做哪些事」的規則。常見的四種模型：

| 模型 | 全名 | 一句話 |
|------|------|--------|
| DAC | 自主存取控制 | 資源擁有者自己決定誰能存取 |
| MAC | 強制存取控制 | 系統用標籤與等級強制規定，使用者無法自行繞過 |
| RBAC | 角色型存取控制 | 依「角色」授權，例如會計、工程師、管理員 |
| ABAC | 屬性型存取控制 | 依「屬性」決定，例如時間、地點、裝置狀態 |

把這張表對回五原則：**最小權限**問的是「這個角色該有多少權限」，**零信任**問的是「每次請求要不要驗證」。系統愈敏感，愈適合往「系統強制」的方向走（MAC 或嚴格 RBAC）；而 `blue-07-iam-zero-trust` 會把身分、條件式存取與零信任的完整架構展開。

## 網路分段：讓攻擊走不動

第二件事是**網路分段（segmentation）**。把整個內部網路連成一張平面，是架構上最常見的致命傷：攻擊者只要突破一台機器，就能在整張網路上橫向移動，一路摸到資料庫。分段的邏輯很直白——**把網切成幾塊，塊與塊之間用防火牆擋住，只允許必要的流量通過**。

典型的分段長這樣：

```text
Internet → 外層防火牆 → DMZ（Web、郵件伺服器）
↓
內層防火牆 ←───────────────┘
↓
內部網路（資料庫、員工電腦）
```

**DMZ（非軍事區）**是刻意放在內外網之間的「緩衝區」：對外服務（Web、郵件）放在這裡，就算被攻破，也進不了內部網路。內部網路再依部門或信任等級切成更小的網段（VLAN），敏感系統（例如只有財務能碰的系統）單獨隔離。

| 分段層級 | 做法 | 保護什麼 |
|---------|------|---------|
| DMZ | 對外服務與內部網路分開 | 內部網路不被暴露的服務連累 |
| VLAN | 依部門／信任等級切網段 | 限制橫向移動的範圍 |
| 微分段（micro-segmentation） | 細到每一台伺服器都有自己的規則 | 把「一台被打穿＝整層失守」變成不可能 |

封包要怎麼在這些網段之間流動？這正是 `net-04-firewalls-vpn-proxy` 的主場——防火牆、VPN、代理伺服器就是分段「落地」的工具。這裡先記住方向：**分段讓攻擊者無法用一次成功換來全部。**

## 安全協定：選對車道

資料在網路上傳輸，就像在公路上開車。你可以走沒有護欄、沒有監視器的小路，也可以走加密車道。**安全協定就是加密車道**——它們保證資料在傳輸途中不會被偷看、被竄改。

| 不安全協定 | 安全替代 | 保護什麼 |
|-----------|---------|---------|
| HTTP | HTTPS（TLS） | 網頁內容的機密性與完整性 |
| Telnet | SSH | 遠端登入的密碼與指令 |
| FTP | SFTP／FTPS | 檔案傳輸的內容 |
| 明文郵件 | SMTPS／STARTTLS | 郵件傳輸 |

> TLS 是網路上最重要的保險絲。 當你在網址列看到 HTTPS 與鎖頭圖示，代表瀏覽器與伺服器之間已經協商出一條加密通道。net-02-tls-https 會把握手、憑證與憑證信任鏈整個拆開講——這條保險絲值得你搞懂它怎麼運作。

選擇安全協定的心法是**「預設加密」**：凡是對外、跨網段、跨網路的流量，一律預設走加密協定；明文協定不是不能用，而是必須有明確理由，且只在完全受控的網段內使用。架構師在設計圖上畫下的每一條「車道」，都應該是加密的。

## 安全基準線：從乾淨的起點出發

想像一百台新伺服器，每台出廠設定都不一樣：有人開著預設帳號、有人跑著用不到的服務、有人密碼留白。**安全基準線（secure baseline）**就是「這台機器在裝好之後，必須長什麼樣」的標準答案——它是整批主機的食譜。

基準線通常包含：移除或停用預設帳號與預設密碼、關閉不必要的服務與連接埠、套用最新版的軟體與安全修補、設定稽核與日誌、統一的金鑰與憑證管理。把基準線寫成文件、再製成**金映像（golden image）**，新機器直接從乾淨的映像部署——這就是 `blue-01-hardening` 的起點。

架構層面要記住的是：**基準線不是「設定一次就結束」**。機器跑久了會產生「設定漂移（drift）」——某人手動改了設定、某個服務被偷偷開啟。所以基準線必須搭配定期檢查，把漂移的機器拉回正軌。

## 雲端安全：責任共擔

雲端沒有改變安全原則，只改變了**誰負責什麼**。這就是「共享責任模型（shared responsibility model）」：雲端廠商負責「雲端本身的安全」，你負責「雲端裡面的安全」。

| 雲端廠商負責 | 你負責 |
|------------|--------|
| 實體機房、主機硬體 | 帳號與權限（IAM） |
| 虛擬化平台、底層網路 | 虛擬機／容器裡面的設定 |
| 託管服務的基礎（如資料庫服務） | 資料的加密與存取控制 |
| 雲端平台本身的修補 | 你部署的應用程式與作業系統 |

實務上最容易犯的錯，是**誤以為「放上雲端＝廠商幫你保安全」**。其實公有雲上大量的入侵事件，都來自配置錯誤：儲存桶沒設權限、管理介面對外開放、金鑰寫在程式碼裡。雲端安全的起點，是把 IAM（身分與存取管理）、加密、網路規則（安全群組）三件事做對。

## IoT：最容易被忽略的設備

印表機、攝影機、溫溼度感應器、門禁控制器……**IoT（物聯網）設備**是安全架構裡最容易被忽略的一塊，偏偏它們往往又便宜、又脆弱、又長期掛在網路上。三個經典問題：

* **預設帳密**：很多設備出廠就是 `admin/admin`，使用者從不更換。
* **不更新**：出廠後不再有修補，漏洞永遠躺在裡面。
* **不能安裝防護**：資源太少，連防毒、代理都很難跑。

> IoT 的分段要「寧可錯殺」。 把 IoT 設備放到獨立的網段，與電腦、手機、資料庫完全隔離。壞處是管理上多一點麻煩，好處是「監視器被入侵」不會變成「公司內網失守」。這是少數可以靠架構解決、卻被絕大多數組織忽略的便宜防禦。

對 IoT 的心法跟對員工一樣：**預設不信任**。假設它隨時可能被入侵，所以給它的權限與網路通道，都要從最小開始。

## 防火牆、VPN、代理在架構裡的角色

把前面幾節串起來看，防火牆、VPN、代理這三種設備其實是架構的「閘門」：

* **防火牆**：在網段邊界決定「誰可以過、什麼流量可以過」——分段的落地工具。
* **VPN**：把不安全的網際網路，變成「暫時的內網通道」——遠端使用者進入內部網路的入口。
* **代理伺服器（proxy）**：代表內部使用者向外請求——既是過濾點，也是隱藏內部架構的屏障。

`net-04-firewalls-vpn-proxy` 會把三者的規則、部署與常見錯誤完整拆解。架構層面只要記住：**這三種設備不是「買來就有效」，它們是架構設計的一部分**——放在哪裡、允許什麼、預設拒絕什麼，都在設計圖上決定。

## 一句話總結

把這一章收進一句話：**安全架構不是「買了什麼」，而是「怎麼設計」**——網路切得夠細、協定走加密、機器從乾淨基準線出發、雲端與 IoT 的責任分清楚，再加上最小權限與縱深防禦，很多攻擊在開始之前就被設計擋掉了。剩下的，就交給下一章的日常營運。

#### Q: 為什麼「網路分段」能顯著提升整體安全？

* 因為它讓攻擊者突破一台機器之後，難以在整張網路上橫向移動

* 因為它可以完全取代防火牆與入侵偵測

* 因為它讓所有對外流量自動加密

* 因為它消除了對最小權限的需求

> 💡 分段把網切成互相隔離的小塊，攻擊者即便突破一台機器，也只能到達同一個網段，無法直接摸到資料庫等敏感系統。其他選項描述的都不是分段做的事。
